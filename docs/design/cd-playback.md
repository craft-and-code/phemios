# Local audio CD playback

## Source and boundaries

Sources musicales → CD audio precedes Concerts in the default navigation and existing menus that have no CD entry. Users can hide, rename or move it through the existing navigation preferences. Opening the native page explicitly discovers optical drives; ordinary offline navigation does not probe drives or start network activity. Browser previews explain that physical playback requires the native application.

The standalone `crates/phemios-cd` workspace member owns read-only optical access through pinned MIT-licensed [cd-da-reader 1.0.0](https://crates.io/crates/cd-da-reader/1.0.0). It has no Tauri, Aède, network or output dependency. Only native-discovered opaque selectors cross IPC; no webview-supplied device or arbitrary source-file path is opened. Selections are temporary: neither source audio, tags, Aède catalogue, personal history nor listening-completion evidence is written or inferred. Track numbers and durations come from a validated TOC. Data tracks are excluded and the upstream CD-Extra session-gap boundary is reused. Unknown semantic titles remain “Track N”. On macOS, Linux and Windows, optional local CD-Text supplies disc/track titles and performers when the medium and drive support it; optional MusicBrainz identification supplements missing physical-disc titles as described below; extraction is not implemented.

## Shared transport and bounded resources

The existing native Player, logical queue actor, CPAL output, consumed-frame clock, volume, spectrum and 24 bands are reused. Play/pause, previous/next, repeat, shuffle, queue removal/reordering, Stop, output selection and exact within-track seeking retain that shared transport. CD sources are anonymous and never federation-qualified into a server account. Footer and Playback links point back to the CD page. Catalogue additions cannot be mixed into a CD queue; playing a catalogue selection replaces it normally.

Audio is CD-DA 16-bit stereo at 44,100 Hz. CPAL requests a supported mono/stereo 44.1 kHz configuration and refuses an unavailable format explicitly; no homemade resampler, whole-track allocation or Aède server is required. Physical CD, BIN, FLAC and WAV do not require FFmpeg; optional APE support does (see below). Host mixing, f32 output and app volume do not establish bit-perfect output. Album-normalization DSP, crossfade and HQPlayer are unavailable for this source rather than silently simulated. Their catalogue preferences are retained.

One isolated optical worker reads at most 27 sectors (~64 KiB) at a time into a two-message channel. One converted pending chunk and the existing half-second ring bound retained audio below one MiB, excluding thread/device overhead. No drive, credential, network I/O or allocation occurs in the audio callback. Pause keeps the bounded prefetched audio. Seek retires old source epochs and uses the callback's existing flush/ramp before admitting the new exact frame. The worker never reads beyond the selected track. A read failure or removed/changed disc is an explicit error; buffered or incomplete sectors cannot become successful output/history claims. A stalled driver can finish after Stop without publishing more audio; an exclusive registry gate refuses a second competing drive operation until that read exits. This is not a hard cancellation guarantee for an OS driver call.

The full-track Aède waveform API is not called for a temporary CD. A progressive source envelope records stereo absolute peaks from chunks already read for playback, outside the audio callback. At most 1,024 nullable buckets (~4 KiB of peak payload, plus Option/container overhead) are retained for the current track. Read prefetch may extend the drawing slightly beyond consumed progress; the consumed cursor remains authoritative. Pause retains the drawing, seeking fills only newly visited regions, unread buckets stay absent, and another track/cleared selection cannot inherit its envelope. No whole-disc read or extra optical reader is started to draw it. The strict native DTO validates attribution, bucket/time bounds and finite peaks. Spectrum/visualizer values still come from actually consumed native PCM.

## Accounts and physical operations

Anonymous CD playback has no server dependency. An authenticated supervised account cannot use an unidentified CD to bypass artist/schedule/quota rules: that source is unavailable for supervised accounts in this first version. Named accounts are rechecked away from optical/output work; unavailable/replaced sessions retire admission. A cached administrator or legacy capability exemption requires a fresh authenticated session confirming the same enabled identity and role, including each recurring permission check. Server-side revocation/demotion cannot retain a stale local exemption. This does not add a server dependency to anonymous CD use. Guest use after logout remains allowed, as with existing account policy. CD references do not read or modify account favourites, lyrics, collections or history.

Refresh remains available without media or a drive so discovery can be retried explicitly, but is unavailable during active/paused CD transport or native source work. Its shared RefreshButton acknowledges an explicit action with at least one second of loader feedback; hovering/focusing the active control exposes Stop, which retires read admission. While this page is visible and no CD selection is active, a five-second insertion probe discovers newly attached/inserted media without replacing the empty view with a page loader. No probe runs while the page is hidden or CD transport is starting/playing/paused. CD tracks and the disc-level Play share CoverPlayView and its centred glyph geometry.

Explicit ejection is unavailable while the selected disc is starting/playing; the native routing guard also refuses a Play/eject race. Ejection of a paused/stopped CD halts retained CD output before asking the OS to eject a previously discovered drive, without shell interpolation. External commands have a ten-second wait; the native macOS framework/driver call has no hard cancellation guarantee.

macOS targets the exact native DiscRecording IORegistry device, including an empty/unreadable drive. If DiscRecording cannot resolve that device at all, a fresh optical-only IOKit inventory must still contain its exact registry identity before `/usr/bin/drutil -drive <unique-product-or-vendor> tray eject` is admitted. Both product and vendor fields are checked for selector collisions using drutil’s observed ASCII case-insensitive matching; numeric prefixes (including `1model` and `+1model`), default/bus/location selectors and ambiguous identical readers are refused. A native ejection refusal never triggers a second attempt through this fallback. The shared fixed-tool runner has no shell or inherited input/output and kills/reaps a child after a ten-second exit deadline. Native selection and tool dispatch are separate operations, not an atomic guarantee against concurrent device replacement. Readable optical devices not enumerated as writers retain the `/usr/sbin/diskutil` fallback. Linux uses `/usr/bin/eject`, and Windows uses a fixed system PowerShell/Shell.Application invocation with a validated optical drive letter. A missing command or refusal remains visible. The application does not request root access or weaken device permissions. macOS raw-device rights and Linux optical-device group permissions may require host configuration; permission failures are distinct from an invented readable disc. Physical-drive recognition, access, ejection, damaged media, actual listening and native Windows/Linux behavior need hardware acceptance.

On macOS, DiscRecording discovers connected writers even when BSD media nodes are absent. A read-only IOKit enumeration of `IOCDBlockStorageDevice` (including DVD/BD subclasses) supplements that snapshot when DiscRecording omits an empty reader. Native IOService identities and vendor/model remain separate from the optional descendant BSD media name; no inserted volume, process, account, network, audio read or new dependency is needed. Owned IOKit/CF references are released on all paths, enumeration is capped at sixteen drives, and matching registry/media identities are merged without replacing a primary label or duplicating the drive. The development Mac diagnostic recognizes the connected ASUS reader with no media through this path; insertion/audio and Windows/Linux acceptance remain separate.

Readable optical media omitted by that writer snapshot also resolves its native BSD name through `DRDeviceCopyDeviceForBSDName` before falling back to a generic label. Vendor/model are combined without duplicating the vendor and bounded for the bridge. DiscRecording can return no devices/metadata in an unbundled development executable even when the system recognizes its readable BSD media. If direct BSD resolution also fails, a fixed `/usr/sbin/diskutil info -plist diskN` read supplies only the system MediaName, admitted against its exact DeviceIdentifier. The existing child-process boundary limits output to 8 KiB with a five-second pipe deadline and a one-second exit wait, then kills/reaps a retired process; failures leave the generic source usable. Apple's immutable property-list parser handles the bounded response without a new dependency. No shell, user-supplied path, privilege change, audio extraction or full-volume scan is involved. This fallback keeps the existing native BSD ejection route. A writer whose media status is not ready is updated in place rather than duplicated. Refresh explains that playing/paused optical transport must first be stopped. Drive identity and an optional readable-media path remain separate; the Eject header button depends on the drive, not on a valid audio TOC. The existing native routing guard still refuses ejection of a starting/playing selected disc.

## Optional CD-Text

All three platforms request at most 32 KiB of MMC format-5 CD-Text, under the existing optical gate and outside active audio playback. The platform boundary is deliberately read-only:

- **macOS:** `DKIOCCDREADTOC` format 5 on the discovered raw media handle.
- **Linux:** `SG_IO` with a fixed ten-byte `READ TOC/PMA/ATIP` command (`0x43`, format `5`), `SG_DXFER_FROM_DEV` and a ten-second driver timeout. A read-only nonblocking handle admits only native `/dev/srN` paths or the discovered `/dev/cdrom` fallback. The [Linux command filter](https://github.com/torvalds/linux/blob/master/drivers/scsi/scsi_ioctl.c) classifies this query as read-safe. The [UAPI header](https://github.com/torvalds/linux/blob/master/include/scsi/sg.h) defines transfer status/residual semantics; ioctl, SCSI, host, driver and impossible transfer-length failures discard the optional metadata.
- **Windows:** [`IOCTL_CDROM_READ_TOC_EX`](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddcdrm/ni-ntddcdrm-ioctl_cdrom_read_toc_ex) with a four-byte [`CDROM_READ_TOC_EX`](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddcdrm/ns-ntddcdrm-_cdrom_read_toc_ex) selecting `CDROM_READ_TOC_EX_FORMAT_CDTEXT`. Only the natively discovered `\\.\X:` volume is admitted. Standard owned file handles request read access and share existing readers/writers; the synchronous `DeviceIoControl` call has no application-imposed hard cancellation deadline. A failed call, partial or oversized response is discarded. No generic pass-through command or write handle is exposed.

A common boundary checks both the number of bytes actually transferred and the length declared by the response before invoking the existing safe Rust parser. That parser validates pack lengths, CRCs, sequence/count tables and one coherent language block before exposing names. ASCII and Latin-1 CD-Text are supported; double-byte/Japanese and other unsupported encodings remain unidentified. Names are bounded and keyed by physical TOC numbers, not by the filtered audio-row index. The TOC is rechecked after optional metadata reading; failure, missing text or unsupported data cannot prevent valid audio playback or alter source bytes. CD-Text itself performs no online lookup, installation, privilege request or permission change. CUE names retain their existing path. Kernel/device calls, including the Linux timeout, cannot establish a hard cancellation guarantee for a stalled driver.

Original synthetic CRC-checked fixtures cover accented Latin-1, disc/track performers, continuation packs, a non-one first track and rejection of incomplete/corrupt/unsupported data. The exact Linux and Windows query/response paths run with simulated synchronous device calls on the Mac host; they exercise native request bytes, read direction, Linux ABI/status/residual checks, Windows transfer sizes and real parser output. The original parser tests retain their behavior/count and share a dedicated test-only fixture builder. Cross-compilation checks cover the library, tests and metadata example for Linux x86_64 GNU and Windows x64 MSVC. These use the installed Rust 1.99 standard-library sources through `RUSTC_BOOTSTRAP=1 cargo -Z build-std=std,panic_abort,test check`, with isolated `/tmp` target directories. They establish compilation, not execution on either target, MSRV acceptance, installer behavior or a working physical CD-Text drive. Production builds remain on the normal documented Cargo commands.

### Physical metadata acceptance

Use a known CD-Text audio disc with ASCII/Latin-1 titles and a reader that exposes it. Many audio discs have no embedded names; a generic “Track N” on such a disc does not establish a failure. Use an ordinary account with the optical-device access already required for playback; do not broaden permissions to force a result. Stop CD playback before discovery.

On a **Linux machine**, with Rust 1.90+ and its native toolchain installed:

```sh
cargo test -p phemios-cd --locked
cargo run -p phemios-cd --example cd_probe --locked -- --metadata
```

On a **Windows machine**, in PowerShell with Rust 1.90+ and MSVC Build Tools installed:

```powershell
cargo test -p phemios-cd --locked
cargo run -p phemios-cd --example cd_probe --locked -- --metadata
```

The read-only example enumerates devices and reports supplied disc/track names without opening audio output, modifying files or contacting a server. Then open the native App’s Audio CD page, compare disc/track titles and performers, start one track and confirm its displayed title. Repeat with an ordinary disc lacking CD-Text and verify generic names and playback remain available. Record OS/App commit, drive model, known CD-Text titles and actual results; cross-compilation alone does not clear this acceptance. If the driver refuses the optional query, names stay unidentified. Never log or share a private library dump unnecessarily.

The maintainer reports that physical Mac ejection works on the current local build; this is manual user evidence, separate from automated checks. A separate diagnostic compiled from the production ejection modules reproduced missing DiscRecording resolution at the development executable location, successfully dispatched the empty ASUS reader through the targeted system fallback, and observed its native tray-open state afterward. This validates that host/device path; the App itself was not rebuilt or launched for this check. Native Linux/Windows and real-disc CD-Text acceptance on all platforms remain pending.

## Verification seams

Sibling Rust tests cover malformed/mixed TOCs, non-contiguous physical numbers, upstream session-gap handling, exact sub-sector seek, bounded/short sector reads, sample conversion and ejection argument confinement. Core/bridge tests cover processing admission, anonymous operation, replacement of the same account's credentials and namespace separation. TypeScript tests cover native DTOs, no-server transport, prepared queue replay and refusal of mixed-source appends. `CdContent` has isolated Storybook states and an explicit track-selection interaction. The read-only `cargo run -p phemios-cd --example cd_probe` example opens no audio output and makes no server request. Software fixtures do not establish physical audio acceptance.

## Disc image scope

The native **Open a CUE image** action admits a selected UTF-8 (optional BOM) CUE of at most 256 KiB. The original audio-only CDRWIN parser supports one or more BIN, FLAC, WAV or APE files, 1–99 ordered AUDIO tracks, INDEX positions and optional TITLE/PERFORMER metadata. Files have 2352-byte little-endian stereo PCM sectors. Stored INDEX 00 gaps remain part of the preceding programme track, as with INDEX 01-to-INDEX 01 optical playback; only the conventional initial two-second PREGAP is admitted outside programme audio. Other added PREGAP/POSTGAP, pre-emphasis/four-channel flags, mixed/data tracks, MOTOROLA and non-CUE image formats are explicitly refused. Later audio files must start at INDEX 01 00:00:00. No claim of complete CUE grammar coverage is made. Format reference: [libcdio CDRWIN BIN/CUE documentation](https://libcdio.github.io/libcdio.html#CD-Image-Formats).

The file picker stays native; IPC accepts no path and exposes no broad filesystem permission. Audio references must resolve to regular `.bin`, `.flac`, `.wav` or `.ape` files inside the selected CUE directory, including subdirectories. Absolute/UNC/drive paths, parent traversal, escaped symlinks, absent/truncated files, inconsistent positions and aggregate images longer than 120 minutes are refused before publication. File handles are read-only and pinned; changed length/modification metadata interrupts reading. One image with at most 99 bounded handles is retained for the process, without mounting, extracting, writing source files or persisting a recent-files/account entry. CUE parsing has no product dependency; Symphonia 0.5.5 is explicitly enabled only for FLAC and WAV/PCM decoding.

The image adapter implements the same bounded sector-reader contract as the optical source. All transport, policy and buffer limits above still apply. Opening/refreshed validation is transactional; an invalid replacement preserves the previously admitted image. Refresh and reselection retain queue references for an unchanged image; changed image layouts require a fresh selection. Closing an image uses the source-close action without an OS eject command. It is disabled while that image is starting/playing. The physical-drive gate remains separate from image handles.

## Compressed and container-backed images

CUE `FILE ... BINARY` accepts BIN. `FILE ... WAVE` accepts WAV, FLAC or APE, as commonly produced by rippers; explicit FLAC/APE type declarations are accepted for their matching extension. A mismatched declaration is refused. All formats retain exactly the same CD-DA contract: stereo, 16-bit, 44,100 Hz, known frame count divisible by 588 and a maximum aggregate duration of 120 minutes. Other rates/depths/channels are refused rather than implicitly resampled or truncated. This is CD-image playback, not a general high-resolution CUE player.

WAV (signed PCM16 little endian) and native FLAC use [Symphonia 0.5.5](https://github.com/pdeljanov/Symphonia/tree/v0.5.5) with only FLAC/WAV/PCM features. Admission reads headers, not the entire programme. A per-playback decoder consumes bounded packets on the existing I/O worker; exact accurate seeking discards decoder pre-roll and preserves CD track boundaries. Decoder state is released when the worker retires. Malformed headers/packets, unsupported precision and truncated streams fail explicitly. Metadata/artwork allocation limits and bounded packet/frame checks supplement the source/file limits. The optical PCM buffer bound excludes codec working memory.

APE is optional through an already installed **FFmpeg and FFprobe with `fd:` support**, found on absolute process PATH entries (plus `/opt/homebrew/bin`, `/usr/local/bin` and `/usr/bin` for a Finder-launched macOS App). Empty/relative search entries are ignored. Neither is installed, downloaded or bundled by Phémios. Probe and decoding receive a clone of the pinned read-only regular-file handle through standard input; no source pathname or arbitrary URL is interpolated. The forced APE demuxer and `fd,pipe` protocol allowlist exclude network protocols. `FFREPORT` is removed, stderr is not exposed and no output file is created. See the [FFmpeg descriptor protocol](https://ffmpeg.org/ffmpeg-protocols.html#fd). An unsupported FFmpeg build or absent executable produces an explicit opening error.

The external decoder has one worker thread, two pipe blocks of at most 27 sectors and one pending block, with a five-second total timeout for a requested read/probe and an 8 KiB probe-output limit. Stop/source retirement drops the per-stream process, kills and reaps it; a seek starts a fresh accurately positioned decoder. No full image is extracted to disk or retained in memory. FFmpeg has its own additional codec/process working memory. Native Windows/Linux descriptor behavior still needs platform acceptance.

Original synthetic WAV/FLAC/APE fixtures and their generator live in `crates/phemios-cd/tests/fixtures`. Tests compare every returned sample across forward/backward/sub-sector seeks, multiple track boundaries and exact EOF; they also reject non-CD-quality WAV, changed compressed files and malformed APE probe fields. APE acceptance is required by `PHEMIOS_REQUIRE_FFMPEG=1` when the verification host supplies FFmpeg/FFprobe. Physical optical hardware remains unverified without a drive.

## Automatic public track identification

When the Audio CD page detects an inserted physical CD with missing titles, it starts one optional MusicBrainz lookup from the already inspected TOC. This is an explicitly requested exception to ordinary offline-navigation enrichment. Complete CD-Text and CUE image names do not trigger it. There is no Aède connection, account history, source-file modification or audio upload. The read-only CD crate only exposes a path-free TOC; `phemios-core::cd_metadata` owns HTTP and `src-tauri` admits the existing opaque token. Native source/routing locks are released before HTTP. Playback can start while identification runs.

The [MusicBrainz non-MBID API](https://musicbrainz.org/doc/MusicBrainz_API#discid) accepts `/discid/-` with a TOC, without adding a hashing dependency. Since this endpoint performs a fuzzy search, automatic names require a returned disc with exactly equal offsets and audio leadout; merely similar durations are insufficient. Matching editions with contradictory names remain unidentified. Unusual non-consecutive/non-one track numbering and images stay local. CD-Extra uses the existing audio-session boundary. Embedded names always win over public claims.

A separate native HTTP lane uses a fixed HTTPS origin, public-only DNS resolver, normal TLS validation, no proxy or redirects, identifiable User-Agent, an eight-second total timeout and a 2 MiB response bound. Requests are serialized at no more than one per second within this client; other applications/Aède share the IP-level provider limit. A process-only cache retains at most 32 TOCs: matched names for 24 hours, absent/ambiguous answers for 30 minutes and failures for 30 seconds. No private account data is cached here. Reopening the CD page can retry after the relevant expiry. Background identification only follows detection in the mounted Audio CD view; there is no system-wide optical poller.

Ejection/replacement and view disposal reject late publication. Stop on an active discovery retires identification admission too. An already dispatched native HTTP request may complete within its deadline and fill the public metadata cache; this does not revive a retired source. No metadata request probes the optical device during playback. Software tests cover native TOC construction, exact-match parsing, ambiguity, bounded cache expiry, malformed input, CD-Text priority and late/cancelled/disposed replies. Real inserted-disc identification and optical playback remain hardware acceptance tasks.
