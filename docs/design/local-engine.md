# Managed Aède and combined catalog

## Request diagnostics

Known Aède internal errors and unreadable-personal-data errors link to **View diagnostics** in Phémios. The native `user_unavailable` code receives specific compatibility guidance without echoing server-controlled messages or recommending a reset/scan. Other internal errors no longer refer to an inaccessible server journal.

The diagnostic dialog contains up to 64 recent JSON-request failures in frontend memory, scoped to the exact current local/server native sessions. It retains time, source, method, a sanitized endpoint label and a fixed error category. Queries, bodies, credentials, account/task/file identifiers and raw response/error text are never retained. Logout/replacement clears that source and closes the dialog; late old-session failures are ignored. This is a client request journal, not captured server stderr, a persistent audit ledger or a diagnosis of every server-side cause. Escape/Close dismisses it without retrying a mutation.

## Authorized scope

Settings replaces the connection button, retains a source-status light and offers local folders plus the existing server connection concurrently. The user chose a combined public catalog with visible Local/Server origins. Personal data and installation operations remain scoped to one actual source/account; matching display names never merge server identities. Settings includes roots/exclusions, explicit scans/fetches, supported account operations, external-service configuration, language preference and eight presentation colours with reset. French/English translation follows a separate commit.

## Engine ownership

A target-specific packaged Aède executable owns scanning, accounts, graph persistence and DSP. Native Phémios starts only this executable against its dedicated app-data store, on an OS-assigned loopback port. Readiness uses a versioned structured reply; the parent's retained stdin is a lifetime lease. Only this owned process is stopped. Existing servers and data paths remain independent. The local principal uses an app-owned protected secret rather than exposing credentials in arguments, browser storage or logs. Corrupt settings/credentials are preserved and refused. Closing the app releases the lease and normal Aède shutdown drains its accepted work.

## Source boundary

Two native client/cache/session contexts remain live. Public presentation references are namespaced before crossing IPC; only validated reference fields are rewritten, never notes, paths or tags. Reference-bearing calls select their originating source; mutations cannot mix origins. Non-entity personal and diagnostic views explicitly select a source, and artwork caches remain per source. Album/discography playback remains on its original source; user labels never route audio.

## Watched folders and unavailable media

Folder selection uses the native directory picker or an explicit native path. Network shares are selected through their OS-mounted folder/UNC path. Registration of Phémios’s embedded local folders is independent of scanning. A disconnected root remains configured and retains cached catalog entries; an unavailable or unmounted folder is not an empty library. Source root operations reuse Aède's roots/exclusion contracts and writer locking. Native preflight and engine retention are covered separately, including mount points that remain as empty directories. Mount/share credentials are owned by the OS; Phémios does not write audio tags or mount a missing destination as a new local directory.

## Credentials and presentation

Fanart.tv and AcoustID keys stay in one private native configuration. Explicit enrichment attaches them only to the supported per-job service-key contract, for both selected libraries by default. Updates/removal apply to the next job without restarting the local engine. The owned engine does not retain these keys in its startup environment. They are never returned as configured values to browser storage. MusicBrainz, Wikipedia, Wikidata and Cover Art Archive do not need a key in the existing Aède profiles. Server installation keys remain unchanged; absent app-owned keys retain the server defaults. An older server is refused before transmitting any shared keys, with an explicit update/restart explanation. HTTPS administrative fetch routes require a current named administrator session; legacy installation tokens are refused there. Language and validated colour preferences are non-secret app presentation data, with malformed stores preserved rather than silently reset.

## Acceptance

Meaningful tests cover source collisions, reference round trips, unrelated text preservation, mixed-origin refusal, isolated caches/annotations, startup lease termination, private configuration refusal, unavailable/remounted roots and colour/language restoration. Native host acceptance uses isolated fictional local and server catalogs, confirms simultaneous browsing and source-specific annotation/playback, roots lifecycle and shutdown, and never changes the user's existing installation. Minimum toolchain, Windows/Linux builds and physical/network-mount acceptance are reported independently.

## Source presentation refinements

The retained public catalog determines whether origin labels are useful. One origin hides redundant labels and follows its active session automatically; two origins display source badges on cover cards, detail headings and track rows. Track browsing has one bounded concatenated Local/Server window, per-source epoch validation, cached pages and explicit partial failures, rather than a source switch or an unbounded full-track download. Namespaced identities remain distinct. Accounts and personal views keep their owner boundary.

Settings uses a compact vertical category rail, changing to horizontal keyboard-accessible tabs on narrow windows. External keys/options are shared; eligible library checkboxes select independent explicit jobs, both enabled initially. Results report each accepted job or failure separately so a partial success is never described as an atomic transaction. Delete icons remove only the app-owned key and preserve the other key and any input draft. Album/track detail Play resumes a matching paused selection without replacing its queue; a different selection or radio starts the requested item explicitly.

## Settings persistence

Language and colours save immediately, with visible errors and Reset. Scan depth/worker count, enrichment categories and selected library exclusions now persist as validated non-secret app preferences, together with the track page size. Sections merge their changes rather than overwriting each other. Malformed stores are preserved and refused; failed writes leave the last confirmed choice selected. Changing these options never starts a scan or enrichment job. Connection and API-key drafts retain their explicit save actions; roots and account operations persist through their existing native/server contracts. Passwords and bearer tokens are not browser preferences.

### Configurable shell

Appearance contains eight independently retained colours and a Reset preserving language. Legacy three-colour preferences retain their former text contrast. Navigation contains visibility checkboxes (all enabled initially), native drag handles, equivalent move arrows and Reset. Changes publish only after device-local persistence; new menus append visibly to a previously saved order. The top-level Settings gear remains reachable even with every sidebar menu hidden. These controls change presentation, never account privileges or server configuration.

Podcast removal presents an inline confirmation for the captured feed. Choosing another feed or Cancel abandons the request; only confirmation writes the subscription store, with a failed write leaving it intact.

Discogs label biographies are an optional persisted enrichment category. Enabling the category does not contact Discogs; explicit enrichment requests label identification then the identifier-linked fallback. No Discogs token is collected for ID lookups. Each source must advertise fetch_discogs before receiving the new flag; rejected legacy jobs explain update/restart. The original server installation keys remain independent.

## Account settings and portable themes

Settings separates Language from Colours/themes. Eight colours preview immediately; Save exports a versioned JSON theme through the native file picker, and Import validates the complete bounded document before applying it. Theme files include colours/name only, never language, sources or credentials. Reset affects colours only. The native import has a 4096-byte read bound. Saved Settings show device/account confirmation or a visible synchronization failure.

The account-preferences capability loads and patches only the nine validated non-secret interface settings: appearance/language, navigation, tool options, duration display, scene, frequency visibility/style, shortcuts and audio policy. Their browser projection uses new versioned profiles partitioned by actual source, remote authority and stable account ID; the managed local authority is independent of its changing loopback port. Anonymous choices occupy a separate device profile. Switching account/source clears the previous projection synchronously before asynchronous reads, and missing fields use neutral defaults rather than inheriting the preceding account. Startup without authentication reads only the anonymous profile. Legacy global setting bytes remain intact, are never attributed automatically and are not an offline fallback for the previous account.

Writes serialize per captured identity/source and carry the exact native process-session ticket. Replaced identities discard late responses and queued changes; a full projection generation also distinguishes returning to the same account. Profile publication is a single JSON write before acknowledgement, preserving the previous projection on storage failure. Hydration replaces the complete confirmed projection while preserving explicit edits made during its read. A delayed crossfade acknowledgement/error admits only its captured interface generation, without changing DSP or transport behavior. Duration hydration updates the visible choice without rewriting a still-held legacy slot for the preceding account; explicit identified-user edits retain that slot's existing compatibility contract. Corrupt private/device/account stores remain explicit and preserved. Device-only use remains supported; older servers show an update/restart explanation and retain saving within the active local profile. Installation roots/accounts/keys and HQPlayer device configuration keep their existing native/server persistence rather than being copied into account preferences.

## Portable preferences and private-document backup

Settings → Backup exports a versioned `phemios-preferences` JSON snapshot through a native save dialog. The nine supported interface settings include effective defaults, appearance/language, navigation order/visibility/literal custom names, keyboard bindings, tool presentation options and playback/visualizer choices. When authenticated, version two also explicitly includes only the selected account's native podcast subscriptions, listened-episode markers and saved Wikipedia article copies. A compact source choice appears only when both accounts are connected; the active account/source is named before export. Anonymous exports remain version-one interface snapshots. Legacy unassigned device stores are neither inspected nor adopted.

Private backups carry bounded source/account attribution for review, not credentials or destination authority. Files contain personal reading/listening information and retained feed/media URLs in plain JSON and must be treated as user-owned backups. Native roots, passwords, bearer tokens, API keys, installation/account configuration, music annotations and audio downloads remain excluded. Colour-only themes retain their separate format and scope. New Unix export files are mode 0600; no cross-platform encryption or inherited Windows ACL guarantee is claimed.

Import accepts prior version-one files within their original 128 KiB budget. Version two has a 12 MiB UTF-8 file budget, with the existing per-store limits (100 podcast feeds, 200 episodes/feed, 4096 listened markers, 4 MiB per podcast array; 40 saved articles, 3 MiB article-array bytes and 512 KiB text/article). Native and frontend validate every private record, duplicate identity and provenance; existing semantic preference parsers admit all nine settings before review. Unknown envelope, origin and preference metadata fields are refused; validated podcast episode extensions are retained. Unreadable native data blocks export and restore rather than appearing as an empty collection.

The explicit review shows origin, counts and the current destination account. Apply replaces the interface snapshot and **adds missing** subscriptions, listened evidence and article editions to the currently selected writable account. Existing feed URLs, article edition/page identities and listened markers win, preserving newer local edits and unrelated records. No owner from the imported file is trusted to select a destination. Anonymous/auditor private restoration is refused. Both current stores and combined quotas are validated before the first private publication; unreadable or exhausted stores retain their existing bytes. The native bridge holds the exact source/session-generation admission and both store locks for bounded private IO, with live server role validation outside those locks.

Podcasts and articles publish as two independent atomic document replacements; this is not a cross-file transaction. An IO failure after the first publication can leave safe additions, reports an interrupted import and permits an idempotent retry. Existing identities and unknown retained document-level extensions are preserved; no automatic eviction or destructive replacement is involved. Cross-process same-owner updates retain the existing documented race limitation. Preferences are applied/acknowledged only after successful private restoration and current-owner revalidation. Browser preference publication retains its rollback protection and reports failed rollback. Restored subscriptions are reloaded with stale-read/mutation-response guards.

Dialog/review work captures both the full requesting profile generation and exact account/source, including same-account relogin. Changes immediately hide a prior review and discard late file/private results. Private export verifies its original native ticket again after the save dialog and before publication, so logout/replacement cannot write the old owner's document. Import does not scan folders or change an active transport's native audio policy; restored playback policies apply when the next transport is prepared.

Navigation schema 5 retains optional per-item names of 1–80 characters. Names remain literal across language changes; unmodified entries use translated defaults. Stable menu identities, headings, visibility and order remain independent of their displayed name. Versions 1–4 retain their migrations; new custom orders are not reclassified as legacy defaults. Reset restores translated defaults, including the French “Diagnostic” label.

## Administrator-owned listening restrictions

Settings → Parental controls manages a selected non-administrator account on its own Aède authority. Policies are not presentation preferences and cannot be changed through the portable preference backup. Local and remote policies remain independent; guest playback remains unrestricted by explicit choice. See the [parental-control contract](parental-controls.md) for the trusted administrative boundary, source-bound cache admission and short listening leases.

## Owned engine TLS

The desktop host generates a fresh rcgen identity for the literal loopback IP for each owned child. The certificate and matching private key travel only through its bounded private stdin bootstrap, never command arguments, disk configuration or WebView IPC. Aède acknowledges protocol 2 with an ephemeral `https://127.0.0.1:PORT` address. Phémios refuses a plaintext/legacy readiness response and admits the public certificate only for that exact owned loopback authority. HTTPS JSON/artwork and WSS PCM use the same rustls trust identity with normal certificate/name verification. No global CA installation, trust-on-first-use, insecure verifier or remote custom-certificate option is introduced. Reusing the child retains that identity; stopping it discards the public pin and a new child gets a new key. Remote servers keep the existing public-root validation and need their own configured valid certificate.

Missing-release cover GET/POST reuse the authenticated session agent. A longer per-request deadline must preserve its certificate roots, connection pool, redirect refusal and status handling; it must not construct a fresh default-trust agent.

The old Aède protocol 1 remains compatible for other parent applications; Phémios now requires protocol 2 for its own embedded engine. Existing local accounts/catalogue/keys remain intact. Generation is performed once per child, outside playback callbacks; no certificate work runs per PCM block.

The explicit host check is `cargo run -p phemios-core --example embedded_tls -- /path/to/built/aede`. It creates only disposable temporary installation data, verifies real HTTPS administrator requests and child reuse, closes the stdin lifetime lease and confirms shutdown before cleanup. It does not certify physical playback or other platforms.

## Separate Aède server application

Aède 0.5.0 also prepares a standalone Tauri server app. It is a server source in Phémios, separate from Phémios's owned embedded local engine. The user explicitly imports its public JSON connection profile through a native file dialog. Native Rust bounds and validates the profile, refuses unknown/private fields, requires HTTPS `127.0.0.1` with an explicit port and admits the certificate before login. Password entry remains separate and ephemeral. The exact certificate authenticates both HTTPS and WSS through the existing pinned client; no global trust store is changed. Reimport the profile when opening a fresh connection panel or changing the port.

`engines.required.json` declares the minimum embedded Aède/FlacCompagnon versions. Every native dev/build selects the latest published stable Aède release, resolves its tag to a SHA, updates the shared-audio dependency/lockfile and fetches dependencies. It then builds the bundled engine from that same cached source using `--locked --offline`. No automatic use of a sibling checkout, an old release binary cache or arbitrary source/binary overrides remains. The selected SHA is included in bundled version metadata.

`npm run engines:check` reports the latest stable source identity without compiling; `npm run engines:update` explicitly performs the same preparation and engine build as native startup. The preparation-only command `node scripts/audio-source.mjs` updates/fetches dependencies without compiling an App. Direct Cargo commands use the existing lock and need that step first when latest-source selection is wanted. GitHub resolves one stable release per workflow and passes the same selection to all build jobs. Network failure or an incompatible release is an explicit failure, not permission to use older code. Published v0.6.1 lacks the new shared crates, so automatic builds require the next stable Aède release.

## Local scan exclusions

The local exclusions panel uses a read-only selectable list and native folder picker. Plus adds exclusion rules, minus removes the selected rules; neither action removes a watched root or an audio file. The full paged roots response is validated and filtered by excluded status. Edits retain their exact local session and view lifetime before later picker results or subsequent folder mutations. Existing catalogue entries are pruned only by the next explicit scan. `cargo run -p phemios-core --example local_exclusions --locked --offline -- /path/to/existing/aede` verifies the scan/exclude/include sequence with disposable silent WAVs and an existing engine.

## Offline server catalogue controls

Device-local visibility hides only the disconnected server projection and survives restart; an active account remains authoritative and visible. Hiding never deletes cache or personal data. Explicit confirmed clearing is available only while disconnected, with native session admission held through removal of that source’s public catalogue/artwork and retained projection. Cache revisions retire disk reads already in flight, including an initially empty retained projection. No WebView-supplied paths are accepted; local cache, credentials and private stores are outside removal scope. Old native hosts explicitly require an update instead of pretending to clear memory only. The settings label explicitly limits removal to the remote server's offline catalogue/artwork copy. It does not erase the Local catalogue, Aède's stored enrichment, or saved private articles; reconnecting/syncing retrieves the server presentation again. Long biography reading uses its separate public article cache.

Server cache removal also captures the native login generation before queued IO; reconnecting and logging out cannot make an older removal eligible again. Remote removal retires only remote image work and resident URLs, retaining local artwork and its in-flight loads. It also retires the previous bulk-warming queue and its progress before restarting warming for the remaining local catalogue, so deferred completion cannot request further removed-server images or publish obsolete errors.

Catalogue synchronization invalidates artwork only for the synchronized source. The other library retains resident object URLs and admitted in-flight image reads, including during scan-driven refreshes; bulk warming still follows the current combined catalogue. A policy change likewise retires only its source’s artwork and resumes warming the admitted catalogue, so a refused supervised reload cannot erase or strand unrelated local/server images. The changed source remains hidden until its catalogue satisfies the current policy.

Public artwork warming resumes immediately after an admitted catalogue publication, independently of the private annotation read. Logging out during annotations retires that private result without stranding the other source’s image queue.

Missing-album suggestions and their private decisions use independent per-source reads and admitted catalogue revisions. A pending remote read cannot delay local publication; a publication or logout on one source does not reread or retire the other source’s decisions. An accepted decision reloads only its own source.

The exclusions panel shares the bounded, scrollable `ObjectList` and multiple-selection policy with Navigation’s available collections. Shift-click or Shift+Up/Down/Home/End extends, shrinks or reverses a range from its original anchor; Ctrl/Command+Shift adds that range to the current selection. Ctrl+A or macOS Command+A selects all rows while this list has focus; Ctrl/Command-click toggles individual rows. A plain click or unmodified arrow navigation returns to one selected row. Focus is separate from the first selected item, so repeated Shift+arrows follow the active endpoint. Replaced owners retire the anchor; removed endpoints recover from the admitted selection. Delete/Backspace or minus removes the selected exclusion rules sequentially, never watched roots or audio files. The first failure stops the batch, refreshes authoritative rules and retains failed/unprocessed rows selected; earlier successful removals are not rolled back. The exact initiating session and view lifetime are rechecked before each subsequent request. After complete removal, the nearest preceding retained row is selected, falling back to the following row. Focus returns to the list for chained removals in the same session. Drag/drop and Alt+Up/Down still reorder one row's presentation only, without an engine mutation or implicit scan. Empty/loading messages are centered horizontally and vertically without asymmetric padding.

Exclusion display order persists on this device per managed-local account, independently of the active remote browsing account. Its dedicated `phemios.exclusion-order.v1:` records contain only SHA-256 fingerprints of the owner and paths; actual rules and paths remain supplied by the authoritative roots API. The bounded, versioned order record is excluded from account synchronization and portable preferences; invalid bytes or failed writes are preserved and reported. Fingerprints are presentation selectors, not authorization or encryption. Unlisted new paths append in server order; removed rules are ignored without rewriting records on read. A renamed path is a new display item.
