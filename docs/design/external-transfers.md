# External music transfers

The External players view discovers mounted removable volumes, mounted shares and MTP storages. Its existing queue search component resolves explicit tracks, albums, principal artist discographies, M3U selections and private collections without starting or altering playback. Selected source files are deduplicated, with a 4096-track limit. Native preview/start selectors are process-scoped; the webview cannot supply destination paths, executable names or shell commands.

The page follows the copy workflow: permanent **Choose music to copy** (left/first) and **Music to transfer** (right/second) panes first, **Destination device** second, then conversion/verification options and the reviewed preview/start controls. The two source panes share one 560 px height token, independent result scrolling and matching right-side scrollbar clearance. Their former opening/closing controls are absent; ordinary queue pickers elsewhere remain dismissible. The native-free `TransferSelection` and `TransferPanel` separate source selection from the destination-dependent recipe. Discovery or an absent destination does not hide or disable source selection; preparing or running a transfer still locks it. No reordering starts copying automatically.

## Contracts and ownership

A local/remote Aède must advertise `original_exports`. Its bounded selected-track plan supplies portable relative components, byte size, watched roots and a source stamp. A changed source is refused by the original transport. Bearer credentials and binary audio remain native; user/administrator roles can export, auditors and supervised accounts cannot. Exact native session/generation guards retire staged and queued work after logout/account replacement. Progress and filenames are hidden when their owner changes. Catalogue music is common; notes, ratings and other private account data are not exported.

The selected destination must remain the discovered native directory/filesystem or exact MTP USB/storage identity. Mounted destinations overlapping any existing catalogue root are refused in both directions. Incoming paths reject traversal, absolute names, Windows streams/device words and non-portable components. These metadata checks do not provide race-proof confinement against a process concurrently replacing ancestor directories, or perfect hardware identity on a device with no unique serial number.

## Copy pipeline

The native job survives view navigation. One original at a time is downloaded into an exclusively created private staging directory, with a 64 KiB transfer buffer, strict announced length, short connection/idle waits and a one-hour request ceiling. Progress publication is capped at ten updates per second; a continuously progressing original may exceed fifteen seconds. The normal Aède scanner reads that isolated track and the existing copy engine writes it with one worker. Unix child work uses reduced scheduling priority where `nice` is available. Originals, their tags and the live library catalogue remain unchanged. Staging is removed on normal completion, failure or cancellation; abnormal OS/process termination can leave private staging to clean later. Keep Phémios open while transferring, especially while an iPod database is being committed.

Profiles include unchanged originals, MP3, AAC/M4A, Opus, FLAC and WAV. Conversion requires installed FFmpeg and retains Aède's policy: only lossless sources are encoded, so a lossy file in a different format remains that original format. A profile is not a promise that every file is playable by every MP3 player. Embedded artwork travels inside the original; this first connection transfers audio rather than arbitrary sidecars or personal annotations.

Verification enables Aède's new-output and existing-output checks. Plain copies are compared byte for byte; converted files receive the engine's duration/readability checks, and existing encodes are compared against a fresh encode. This is not physical media durability or a full decoded-sample comparison. Replacement is opt-in and unavailable for MTP/iPod. FAT/exFAT may require explicit replacement because their filesystems lack the atomic no-replace hard-link primitive used by Aède. Completed files survive a failed/canceled job; the first failure stops this selection with retained counts and diagnostics. The stop button requests the end of the current filesystem/iPod operation; native downloads and MTP chunks can stop earlier. There is no forced termination in the middle of an iPod database transaction.

Preview lists original sizes and up to thirty **output** relative paths, without a destination write. The additive `export_conversion_plans` capability and explicit profile ask Aède to project each isolated staged source through the same codec-aware conversion/portable-name rules used by its copy engine. Source components/stamps remain unchanged for retrieval and staging. Lossy sources retain their existing format, AAC outputs use `.m4a`, and a missing conversion capability refuses the preview rather than guessing extensions. Converted file/file and file/directory collisions across all batches are refused before any write. iPod automatic mode keeps its separate podkit/database explanation. Conversion sizes remain estimates, and current-file space is checked by the engine/device. A large selection may still fill a destination after earlier tracks have completed; the UI does not claim a reservation of the entire final size. Origins are separated into local/server folders when both contribute files. Path collisions across plan batches are refused rather than merged silently.

## Device adapters

`crates/phemios-transfer` is independent of Tauri, catalogue semantics and credentials. It owns destination identity, bounded tool orchestration, native MTP and the optional iPod adapter. MTP uses the approved pinned `mtp-rs` 0.33.0 with existing futures/bytes dependencies. Uploads preserve existing files, optionally reread them before skipping, and remove only new partial object handles after failure. Directory metadata is streamed; unreadable or ambiguous entries prevent writes. Its virtual-device feature is test-only. Hardware-specific permissions, old-player protocol quirks and device-side media indexing still require actual hardware acceptance.

Apple firmware uses separately installed [podkit](https://jvgomg.github.io/podkit/), with an isolated config, cleared inherited `PODKIT_*` overrides, an already initialized iTunesDB and additive music sync with `--skip-upgrades`. No delete, reset, initialize, format or forced metadata change is exposed. OS ejection is a separate explicit action, independent of database transfer compatibility. podkit handles device-specific ALAC/AAC conversion and database/artwork updates; Phémios does not claim byte verification of that adapter. On macOS, exact BSD-volume membership under an Apple USB node identifies known classic, mini, video, photo, nano and shuffle families without exporting USB serial numbers. A bounded local property-list decoder reuses quick-xml; model silhouettes use the existing SVG icon vocabulary. USB IDs follow [usb.ids](https://github.com/usbids/usbids/blob/master/usb.ids). Unknown devices retain a generic icon and no claimed model. Known unsupported Nano 6/7 and Shuffle 3/4 models are disabled with the incompatibility reason; installing podkit cannot make them compatible. A missing compatible iTunesDB and a missing podkit executable have separate prerequisite messages. Rockbox remains an ordinary-file adapter. Supported classic/mini/video/photo/early nano/shuffle models depend on podkit/libgpod; unsupported later Nano/Shuffle generations and iPod Touch/iPhone/iPad must not be described as working. See its [compatibility table](https://jvgomg.github.io/podkit/devices/supported-devices/). Rockbox installations detected through `.rockbox` use ordinary folder copies. No firmware changes or system-wide tool installations are performed by Phémios.

## Verification and acceptance

Behavioral tests exercise untrusted paths, mount replacement/source overlap, exact owner replacement, original-byte streaming/cancellation, recipe validation and a real Aède scan/copy/read-back pipeline into a temporary destination. MTP tests use a registered virtual device and preserve existing equal/different files. Storybook exposes recipe preview, copying, iPod prerequisites and failure presentation; it never writes a device. The authoritative gate passes the exact prepared Aède executable to the native transfer integration test through `PHEMIOS_TRANSFER_ENGINE`.

These checks do not establish physical iPod, HDD, MP3 or Windows/Linux interoperability. The device owner must review a preview and start the transfer on real hardware. Optional podkit is not bundled or installed automatically. An older running Aède needs an update/restart before the new export endpoints become available.

## Explicit ejection (macOS)

Each ejectable physical mounted destination has an Eject icon, including an unsupported iPod. The webview passes only its registered native token. Native discovery, preview, start and ejection share one admission lease; running work refuses ejection regardless of UI state. The mount's filesystem/directory identity, diskutil BSD identifier, mount point, external status and ejectable flag are rechecked before a fixed, non-forced `diskutil eject` call. Busy/failed/timed-out requests report uncertainty and never claim a safe unplug. Confirmed ejection retires that token and every prepared preview; rediscovery clears the UI selection before new opaque tokens are registered. Discovery during a running job returns its retained inventory.

No shell command, force-unmount, formatter or initializer is exposed. The action has a fifteen-second process bound and a fixed output bound. Linux, Windows, network shares and MTP do not yet advertise this eject capability: use their OS removal workflow. This is not proof against an independent privileged process physically replacing devices at the final OS-call boundary.

A read-only host probe on 2026-10-18 recognized the connected Nano 7 USB model and its ejectable mount. No real iPod was written or ejected. Core fixtures cover multiple connected models, bounded XML and replaced/internal/unmounted disks; native fixtures refuse unknown IDs and overlapping/running operations. Storybook covers unsupported-copy/enabled-eject and transfer-locked ejection. Physical safe removal and supported-model transfer remain owner-operated acceptance.

## Presentation boundaries

The destination card positions its own discovery indicator and retains its last laid-out idle height while discovery replaces the list; initial discovery uses the common minimum height. A scoped ResizeObserver follows idle content/window geometry and disconnects on unmount. Clearing a selection in the same refresh action cannot shrink the loading card. Completed discovery can naturally reflect a changed device inventory. Music selection and transfer options are not overlaid by this activity. Selection and ejection share the existing form-control height; only adjacent destination rows have a separator. The complete transfer page contributes its intrinsic content height to the main scroller, preserving the shared bottom padding even when preview/progress make it taller than the viewport. The transfer-only picker scroller shifts 12 px toward the right panel edge with matching content clearance; the selected-music scroller retains its 6 px offset. The selected-file list fills its pane without moving its count footer; queue composition elsewhere is unchanged.

Nano 6/7 incompatibility is an adapter/database constraint rather than a statement that older iPods are unusable. Many earlier models are supported by podkit. Apple's separate [Mac synchronization workflow](https://support.apple.com/fr-fr/guide/mac-help/mchl923c1147/mac) remains an option for the unsupported Nano; a future compatible-file preparation/export handoff would not itself provide direct Nano database synchronization. No Apple automation or additional adapter is currently implemented.

## Native-picked destination folders

**Choose a folder…** uses the already approved native dialog plugin and accepts no webview path argument. Cancellation preserves current destination state and preview. An accepted existing directory becomes a process-local opaque mounted target, reusing the exact same original-download, conversion, verification and source-owner pipeline as detected drives. Selecting a detected HDD root reuses its physical-volume adapter/ejection metadata; a nested or local folder has no invented ejection capability. Only the latest manual folder is retained in memory. Rediscovery re-registers it if its filesystem/directory identity still matches and otherwise retires it. A failed optional mount/MTP backend does not hide an explicitly granted valid folder; its warning remains visible.

Canonical aliases are deduplicated natively, including Windows drive/UNC paths. Leaf symlinks, replaced directories and stock-iPod ancestors are refused; a subdirectory cannot bypass the Apple database adapter. Rockbox remains an ordinary file target. Both directions of overlap with watched source roots are refused during the existing preview admission. Neither choosing a folder nor preparing a preview writes music. The directory must already exist; creating and populating a directory outside the library remains a separate user action. Account-owned export restrictions still apply.

Verification uses temporary directories and the existing engine binary: a streamed original is copied and read back through a native-picked-folder identity, preserving source bytes and an unrelated destination file. These checks do not establish physical HDD removal, all conversion codecs or another platform's native dialog acceptance. No dependency or system-wide tool is installed.

The picker's bottom-right arrows reuse the shared Pagination component in compact mode. Both remain present: Previous is disabled on the first page, Next is disabled without another 50-result page, and both are disabled during a read. The controller's next-page fact admits unknown totals without inventing a count; other paginated views retain their range/total summary. Glyphs, hit targets, gaps and tooltips are shared. Reordering the panes changes DOM/keyboard order too, including the stacked narrow layout.

## Forgetting a manual destination

A manual folder row has a Remove action separate from physical ejection. Its opaque native token is accepted only while destination admission is idle and only for a registered folder row. Forgetting removes its retained folder identity, target and inventory row and retires any prepared preview; later discovery cannot restore that manual grant. It never removes, modifies or ejects the directory or its contents. Unknown/retired tokens, physical volumes and active transfer work are refused.

When no destination is selected, the conversion recipe resets to unchanged originals, verification enabled and replacement disabled; its controls are unavailable until another selection. Confirmed discovery losing a selected token also clears it. An in-progress discovery alone does not retire its current selection. Source music selection remains independent. The existing iPod automatic profile and MTP replacement restrictions still apply when choosing another adapter.
