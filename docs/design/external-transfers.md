# External music transfers

The External players view discovers mounted removable volumes, mounted shares and MTP storages. Its existing queue search component resolves explicit tracks, albums, principal artist discographies, M3U selections and private collections without starting or altering playback. Selected source files are deduplicated, with a 4096-track limit. Native preview/start selectors are process-scoped; the webview cannot supply destination paths, executable names or shell commands.

## Contracts and ownership

A local/remote Aède must advertise `original_exports`. Its bounded selected-track plan supplies portable relative components, byte size, watched roots and a source stamp. A changed source is refused by the original transport. Bearer credentials and binary audio remain native; user/administrator roles can export, auditors and supervised accounts cannot. Exact native session/generation guards retire staged and queued work after logout/account replacement. Progress and filenames are hidden when their owner changes. Catalogue music is common; notes, ratings and other private account data are not exported.

The selected destination must remain the discovered native directory/filesystem or exact MTP USB/storage identity. Mounted destinations overlapping any existing catalogue root are refused in both directions. Incoming paths reject traversal, absolute names, Windows streams/device words and non-portable components. These metadata checks do not provide race-proof confinement against a process concurrently replacing ancestor directories, or perfect hardware identity on a device with no unique serial number.

## Copy pipeline

The native job survives view navigation. One original at a time is downloaded into an exclusively created private staging directory, with a 64 KiB transfer buffer, strict announced length, short connection/idle waits and a one-hour request ceiling. Progress publication is capped at ten updates per second; a continuously progressing original may exceed fifteen seconds. The normal Aède scanner reads that isolated track and the existing copy engine writes it with one worker. Unix child work uses reduced scheduling priority where `nice` is available. Originals, their tags and the live library catalogue remain unchanged. Staging is removed on normal completion, failure or cancellation; abnormal OS/process termination can leave private staging to clean later. Keep Phémios open while transferring, especially while an iPod database is being committed.

Profiles include unchanged originals, MP3, AAC/M4A, Opus, FLAC and WAV. Conversion requires installed FFmpeg and retains Aède's policy: only lossless sources are encoded, so a lossy file in a different format remains that original format. A profile is not a promise that every file is playable by every MP3 player. Embedded artwork travels inside the original; this first connection transfers audio rather than arbitrary sidecars or personal annotations.

Verification enables Aède's new-output and existing-output checks. Plain copies are compared byte for byte; converted files receive the engine's duration/readability checks, and existing encodes are compared against a fresh encode. This is not physical media durability or a full decoded-sample comparison. Replacement is opt-in and unavailable for MTP/iPod. FAT/exFAT may require explicit replacement because their filesystems lack the atomic no-replace hard-link primitive used by Aède. Completed files survive a failed/canceled job; the first failure stops this selection with retained counts and diagnostics. The stop button requests the end of the current filesystem/iPod operation; native downloads and MTP chunks can stop earlier. There is no forced termination in the middle of an iPod database transaction.

Preview lists original sizes and up to thirty planned relative paths, without a destination write. Conversion sizes remain estimates, and current-file space is checked by the engine/device. A large selection may still fill a destination after earlier tracks have completed; the UI does not claim a reservation of the entire final size. Origins are separated into local/server folders when both contribute files. Path collisions across plan batches are refused rather than merged silently.

## Device adapters

`crates/phemios-transfer` is independent of Tauri, catalogue semantics and credentials. It owns destination identity, bounded tool orchestration, native MTP and the optional iPod adapter. MTP uses the approved pinned `mtp-rs` 0.33.0 with existing futures/bytes dependencies. Uploads preserve existing files, optionally reread them before skipping, and remove only new partial object handles after failure. Directory metadata is streamed; unreadable or ambiguous entries prevent writes. Its virtual-device feature is test-only. Hardware-specific permissions, old-player protocol quirks and device-side media indexing still require actual hardware acceptance.

Apple firmware uses separately installed [podkit](https://jvgomg.github.io/podkit/), with an isolated config, cleared inherited `PODKIT_*` overrides, an already initialized iTunesDB and additive music sync with `--skip-upgrades`. No delete, reset, initialize, format, forced metadata change or eject command is exposed. podkit handles device-specific ALAC/AAC conversion and database/artwork updates; Phémios does not claim byte verification of that adapter. Missing podkit disables its destination and shows the prerequisite. Supported classic/mini/video/photo/early nano/shuffle models depend on podkit/libgpod; unsupported later Nano/Shuffle generations and iPod Touch/iPhone/iPad must not be described as working. See its [compatibility table](https://jvgomg.github.io/podkit/devices/supported-devices/). Rockbox installations detected through `.rockbox` use ordinary folder copies. No firmware changes or system-wide tool installations are performed by Phémios.

## Verification and acceptance

Behavioral tests exercise untrusted paths, mount replacement/source overlap, exact owner replacement, original-byte streaming/cancellation, recipe validation and a real Aède scan/copy/read-back pipeline into a temporary destination. MTP tests use a registered virtual device and preserve existing equal/different files. Storybook exposes recipe preview, copying, iPod prerequisites and failure presentation; it never writes a device. The authoritative gate passes the exact prepared Aède executable to the native transfer integration test through `PHEMIOS_TRANSFER_ENGINE`.

These checks do not establish physical iPod, HDD, MP3 or Windows/Linux interoperability. The device owner must review a preview and start the transfer on real hardware. Optional podkit is not bundled or installed automatically. An older running Aède needs an update/restart before the new export endpoints become available.
