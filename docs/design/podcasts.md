# RSS podcast subscriptions

Podcasts sits beside Radio under Music sources. A user explicitly adds a public RSS/Atom URL or refreshes an existing subscription. Opening/navigating the page reads retained local metadata only and never starts audio or fetches a feed automatically. The first version has no directory, account requirement, OPML import or automatic episode download.

The native ureq client is separate from Aède authentication. URLs exclude credentials, local files, fragments and non-HTTP(S) schemes; only ordinary HTTP(S) ports are allowed. Its resolver checks the actual socket addresses used by every initial/redirected connection, refusing private/link-local/loopback/non-public addresses. DNS and the entire request are bounded; redirects stop after three and XML bodies after eight MiB. No Aède bearer, service key or cookie is sent. Only UTF-8 XML is accepted in this version. One serialized native reader bounds concurrent feed work.

The system WebView parses XML, refusing DTD/entity declarations and parser errors. RSS audio enclosures and Atom enclosure links become finite episodes; HTML summaries are shown only as bounded plain text, never inserted markup. Missing durations/dates remain unknown. Stable episode IDs remove repeats; the newest 200 available entries are retained. Relative enclosure addresses use the supplied feed address. Media URLs exclude embedded credentials and obvious local/private literal hosts. Finite audio uses the WebView’s supported codecs and system output, like Radio; it does not claim CPAL output selection, DSP or bit-perfect playback.

Subscriptions and retained episode metadata live in the application’s local preference storage independently of Aède accounts (versioned document, at most 100 subscriptions/four MiB). Writes succeed before UI confirmation. Malformed/unreadable documents are preserved and shown as errors; there is no silent reset. Refresh replaces only that feed’s metadata; unsubscribe removes only its retained subscription and can be reversed by subscribing again. No source audio file or Aède music annotation/history is touched.

Podcast, radio and library playback are mutually exclusive. The footer exposes finite duration/position, pause/resume without rejoining or resetting, seek, mute/volume and attached Stop. Late starts cannot revive stopped media; stalled/unsupported streams fail visibly. Feed refresh and navigation never imply playback. Offline subscriptions remain browsable; episode audio requires its publisher’s availability. Physical sound, cross-platform codecs and other providers remain separate acceptance work.

Subscription acquisition exposes activity beneath the input row. Refresh instead replaces its own glyph with an accessible spinner for the real request lifetime, restoring the glyph on success or failure; both actions prevent concurrent feed requests.

## Explicit episode downloads

Each episode offers a download action before Play. Native downloads stream into `Downloads/Phémios/Podcasts` with a sanitized episode title and MIME-derived audio extension; existing copies are retained using a numbered suffix. Metadata browsing never downloads audio automatically. A loader replaces the download icon for the actual transfer lifetime and a shared dismissible message reports the saved path or failure. One native download is allowed at a time; feed updates remain independent. Leaving the page does not interrupt a requested transfer or publish late feedback into another page.

The dedicated client reuses the public-address resolver for every initial and redirected connection, never sends Aède authentication, has a twenty-minute deadline/five-redirect limit and streams at most one GiB with bounded memory. XML/HTML/playlist responses are refused; supported finite media are MP3, MP4/M4A, Ogg/Opus, AAC, WAV and FLAC. Oversize, empty, truncated or interrupted responses do not publish an episode. Temporary files are removed on ordinary failure; completed files are published without replacing existing paths. Downloads are standalone files opened outside Phémios; subscription playback still uses the publisher URL, rather than claiming an offline episode cache. Tests exercise stream interruption, limits, duplicate preservation, safe names and real HTTP redirect/truncation handling with a test-only resolver.

## Listened episode evidence

Episode markers are local to this device, independent of Aède accounts like the subscription store. A feed URL plus publisher episode ID identifies evidence, so refreshes, media URL changes and subscription removal do not erase a listened marker. The native browser media adapter supplies actual `HTMLMediaElement.played` ranges. Their union must cover at least 90% of a known finite duration; seeking, elapsed wall time, overlapping/repeated ranges and reaching the end alone do not qualify. Timed updates or natural completion can publish the marker once for the current media generation. Late callbacks from a replaced episode are ignored.

The separate versioned store retains at most 4096 markers and 4 MiB, refuses malformed records and publishes a mark only after persistence succeeds. It neither evicts personal evidence automatically nor implicitly overwrites unreadable data. A visible failure leaves existing evidence intact. This marks podcast playback only; it does not add music history or infer a trophy from a podcast.

## Pending transport attempts

The finite episode lifetime and an individual `play()` attempt have separate tickets. Pause invalidates its pending start/resume result before calling the media adapter and keeps the same media element, source and position. An older rejected promise cannot turn a newer paused or successfully resumed episode into an error. The current attempt's genuine playback failure still releases the media and exposes the existing error. Stop, replacement and application disposal invalidate both lifetimes.
