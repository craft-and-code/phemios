# RSS podcast subscriptions

Podcasts sits beside Radio under Music sources. A user explicitly adds a public RSS/Atom URL or refreshes an existing subscription. Opening/navigating the page reads retained local metadata only and never starts audio or fetches a feed automatically. Subscriptions and listened evidence require a connected Aède account; public feed/media transport remains independent of its credentials. This version has no directory, OPML import or automatic episode download.

The native ureq client is separate from Aède authentication. URLs exclude credentials, local files, fragments and non-HTTP(S) schemes; only ordinary HTTP(S) ports are allowed. Its resolver checks the actual socket addresses used by every initial/redirected connection, refusing private/link-local/loopback/non-public addresses. DNS and the entire request are bounded; redirects stop after three and XML bodies after eight MiB. No Aède bearer, service key or cookie is sent. Only UTF-8 XML is accepted in this version. One serialized native reader bounds concurrent feed work.

The system WebView parses XML, refusing DTD/entity declarations and parser errors. RSS audio enclosures and Atom enclosure links become finite episodes; HTML summaries are shown only as bounded plain text, never inserted markup. Missing durations/dates remain unknown. Stable episode IDs remove repeats; the newest 200 available entries are retained. Relative enclosure addresses use the supplied feed address. Media URLs exclude embedded credentials and obvious local/private literal hosts. Finite audio uses the WebView’s supported codecs and system output, like Radio; it does not claim CPAL output selection, DSP or bit-perfect playback.

Subscriptions and retained episode metadata live in bounded native documents private to the source, server authority and stable account ID (at most 100 subscriptions/four MiB). Native account identity selects the filename; the WebView supplies no owner ID or pathname. Managed Local uses its stable engine authority rather than its changing loopback port. The account’s process-generation ticket admits reads and mutations; users/admins may write, auditors remain read-only. A mutation checks the server’s current account/role outside the file lock before rechecking native generation at the local commit. Legacy device-wide localStorage is retained intact and is neither displayed nor assigned to a connected account automatically. Writes succeed before UI confirmation. Malformed/unreadable documents are preserved and shown as errors; there is no silent reset. Refresh replaces only that feed’s metadata; unsubscribe removes only its retained subscription and can be reversed by subscribing again. No source audio file or Aède music annotation/history is touched.

Podcast, radio and library playback are mutually exclusive. The footer exposes finite duration/position, pause/resume without rejoining or resetting, seek, mute/volume and attached Stop. Late starts cannot revive stopped media; stalled/unsupported streams fail visibly. Feed refresh and navigation never imply playback. Retained subscriptions remain browsable while their owner is connected; logout/source replacement immediately hides the old account’s state and stops its podcast playback. Episode audio requires its publisher’s availability. Physical sound, cross-platform codecs and other providers remain separate acceptance work.

Subscription acquisition replaces the glyph inside the shared Subscribe action for the request lifetime, without changing button dimensions. Refresh instead replaces its own glyph with an accessible spinner for the real request lifetime, restoring the glyph on success or failure; both actions prevent concurrent feed requests.

## Explicit episode downloads

Each episode offers a download action before Play. Native downloads stream into `Downloads/Phémios/Podcasts` with a sanitized episode title and MIME-derived audio extension; existing copies are retained using a numbered suffix. Metadata browsing never downloads audio automatically. A loader replaces the download icon for the actual transfer lifetime and a shared dismissible message reports the saved path or failure. One native download is allowed at a time; feed updates remain independent. Leaving the page does not interrupt a requested transfer or publish late feedback into another page.

The dedicated client reuses the public-address resolver for every initial and redirected connection, never sends Aède authentication, has a twenty-minute deadline/five-redirect limit and streams at most one GiB with bounded memory. XML/HTML/playlist responses are refused; supported finite media are MP3, MP4/M4A, Ogg/Opus, AAC, WAV and FLAC. Oversize, empty, truncated or interrupted responses do not publish an episode. Temporary files are removed on ordinary failure; completed files are published without replacing existing paths. Downloads are standalone files opened outside Phémios; subscription playback still uses the publisher URL, rather than claiming an offline episode cache. Tests exercise stream interruption, limits, duplicate preservation, safe names and real HTTP redirect/truncation handling with a test-only resolver.

## Listened episode evidence

Episode markers are local to this device and private to the same source/authority/account identity as subscriptions. A feed URL plus publisher episode ID identifies evidence, so refreshes, media URL changes and subscription removal do not erase a listened marker. The native browser media adapter supplies actual `HTMLMediaElement.played` ranges. Their union must cover at least 90% of a known finite duration; seeking, elapsed wall time, overlapping/repeated ranges and reaching the end alone do not qualify. Timed updates or natural completion can publish the marker once for the current media generation. Late callbacks from a replaced episode or account/source are ignored.

The private podcast document retains a separate collection of at most 4096 markers and 4 MiB, refuses malformed records and publishes a mark only after persistence succeeds. It neither evicts personal evidence automatically nor implicitly overwrites unreadable data. A visible failure leaves existing evidence intact. This marks podcast playback only; it does not add music history or infer a trophy from a podcast.

## Pending transport attempts

The finite episode lifetime and an individual `play()` attempt have separate tickets. Pause invalidates its pending start/resume result before calling the media adapter and keeps the same media element, source and position. An older rejected promise cannot turn a newer paused or successfully resumed episode into an error. The current attempt's genuine playback failure still releases the media and exposes the existing error. Stop, replacement and application disposal invalidate both lifetimes.

Native text limits count UTF-16 code units to match the WebView validator. Parseable feed dates normalize to `Date.toISOString()` before persistence; native admission validates that canonical calendar/time representation, signed six-digit years and JavaScript Date bounds. Invalid payloads and malformed retained documents are refused without replacing existing bytes. See the [account-isolation report](../coding/account-isolation.md) for session, filesystem and revocation limits.
