# Reviewed player annotation imports

Settings > Imports offers a real Roon album-export workflow. Audirvana and Tune controls remain explicitly unavailable pending a verified personal-annotation export contract. This first adapter handles album favourites, integer personal stars, tags and notes only when the chosen file actually contains them. It does not read proprietary databases/backups, copy audio, edit embedded tags, import listening history or invent a migration of streaming-only entries. Artist/track annotations and playlist migration remain separate work.

## Provider evidence

[Roon export documentation](https://help.roonlabs.com/portal/en/kb/articles/export) confirms CSV Soundiiz snapshots and Excel album exports, but does not guarantee personal star/tag/note fields. Excel must be explicitly saved as UTF-8 CSV before selection; XLSX is not parsed. [Roon rating documentation](https://help.roonlabs.com/portal/en/kb/articles/faq-where-do-an-album-s-star-ratings-come-from-can-i-change-them) distinguishes AllMusic editorial ratings from per-profile personal ratings. Identity headers can be suggested; all private-field mappings start disabled. A separate unchecked choice marks every matched album as a favourite only when the user identifies the file as an export filtered to favourites.

[Audirvana's playlist export contract](https://help.audirvana.com/en/support/solutions/articles/202000071440--c%C3%B3mo-exportar-e-importar-una-lista-de-reproducci%C3%B3n-) confirms M3U and optional relative paths, which cannot encode its personal ratings/notes contract. Tune's [Roon migration guide](https://mozaiklabs.fr/blog/migrate-roon-to-tune-30-minutes), [architecture](https://mozaiklabs.fr/architecture) and [plugin guide](https://mozaiklabs.fr/blog/build-your-first-tune-plugin-in-5-minutes) describe receiving Roon material and custom plugin APIs, without a verified exporter schema for Tune-owned annotations. The disabled controls identify that evidence limit, rather than pretending to perform a transfer. Provider documentation was reviewed on 2026-10-12.

## File admission and matching

The WebView's standard file chooser grants access to the single explicitly selected CSV/TSV. No filesystem plugin, arbitrary path IPC, provider credentials or new dependency is needed. File selection and parsing are limited to eight MiB, 5000 data rows, 32 columns and 16384 code units per cell. UTF-8 is decoded strictly. Comma, semicolon and tab separators, BOM, CRLF, doubled quotes and multiline notes are supported; duplicate/empty headers, control characters, unterminated quotes and ragged rows fail visibly. Formula-like text remains inert data.

The preview builds a bounded identity index from the selected source's retained catalogue. Normalized artist name and album title must match exactly; an explicitly mapped year further restricts editions. Ambiguous, missing, invalid and repeated destinations are never silently selected. The first hundred preview rows show source line, title, artist, desired private values and status; totals and confirmation apply to all admitted rows. Source selection chooses one destination account even when Local and Server share the visible catalogue.

Only 1–5 integer personal ratings are accepted; zero/empty ratings, false favourites and blank notes do not clear existing values. Tags have an explicitly chosen separator and are merged without removing the currently read values. Different existing ratings or nonempty notes skip the whole row. Current server tag/body limits are checked before mutation. Export names, imported values and previews are ephemeral, cleared on source/account change or view disposal, and are excluded from public caches and portable backups.

## Explicit writes and limits

Confirmation serializes existing authenticated annotation GET/PUT requests, carrying the captured native session generation and source. It reads each annotation again before deciding the patch. Auditor accounts cannot import. Wrong outer/nested targets and malformed confirmations fail; only exact saved replies update the current-owner projection. Logout/account replacement suppresses late results and remaining requests. Stop allows an already admitted write to be confirmed, then starts no further row. Failures never trigger an automatic retry, and confirmed prior rows remain stored. A new explicit preview is required to continue after completion or interruption.

This adapter reuses Aède's ordinary field-patch API rather than a transactional bulk endpoint. A separate client writing the same annotation between its final GET and PUT remains subject to that API's last-write semantics; the preview and refresh do not promise compare-and-swap isolation or an all-or-nothing import. Source audio and another account's records are outside the requested operations. Tests use fictional exports and injected private ports. Native acceptance uses only an isolated synthetic catalogue; importing an actual Roon-generated export with all these optional columns remains separate acceptance work.

`SettingsImports` is a composition surface beyond the usual module-size guideline because the same ephemeral review/owner lifetime controls its file chooser, confirmation and progress. CSV parsing, matching/additive patch policy and serial writes live in separate independently tested modules; presentation mapping and preview also have standalone Storybook scenarios.
