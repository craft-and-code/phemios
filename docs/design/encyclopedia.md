# Encyclopedia contracts

## Local reference and explicit public exploration

The existing 25 original bilingual reference entries remain bundled, attributed and available without an account or network. Their category/text search is unchanged. Separate Wikipedia and Saved articles tabs distinguish external text from project editorial content. The compact sliding FR/EN switch shares the top toolbar at its right edge; click/Space toggles its edition and Left/Right chooses FR/EN; choosing an edition does not change the application language. Reference cards and search rows use the same accent hover border as artwork; the non-interactive reader frame keeps its normal border. Choosing a tab or reopening a saved article never fetches content. Explicit edition switching follows the current article rather than returning to an empty form; switching an existing search repeats its current query in the chosen edition. The Wikipedia search form is explicit, has a 200-character limit, and returns at most twenty main-namespace titles. Queries are sent to the selected French or English Wikipedia edition; they never include Aède identity or credentials.

`core::encyclopedia` owns a fixed-host HTTPS MediaWiki Action API client, independent of Tauri and Aède sessions. `src-tauri::encyclopedia` exposes only versioned search(language, query), article(language, page ID), and translate(source language, source page ID, target language) commands, with a single bounded active-request gate. Hostnames are constructed from the two permitted languages, public DNS policy is reused, redirects/proxies are disabled, the descriptive User-Agent links to the related Aède project site, requests have a 15-second deadline and query responses are capped at one MiB; revision-render responses used for resources are capped at four MiB. Search snippets are not requested or interpreted. IDs, namespace, page count, revision and text are validated before returning typed projections; the frontend validates again. Service errors, empty/missing extracts, limits and network failures are visible, not replaced with invented reference content. Browser preview has no external request capability.

## Reading and attribution

Article reading uses `prop=extracts|info`, `explaintext=1`, `exsectionformat=wiki`. TextExtracts is a stable read API with known extraction limitations and no active new-feature maintenance. It provides text rather than a complete rendering: images, tables and some references are omitted. The reader labels this limitation and links to the original. Heading markers become semantic local headings, and all other content is literal Solid text; no remote HTML, scripts, styles or media are loaded. Text has a 512 KiB native limit. No article text is bundled into the product or tests from Wikipedia.

Each copy retains edition, page ID, title, full received text, revision reported by the same query, and retrieval timestamp. Attribution links are built locally from validated identifiers: current article, reported revision, author/history page, and CC BY-SA 4.0 licence. The API extract is not a byte-for-byte historical revision export; extraction can omit material and reflect service caching. Consult the original revision/history for complete wording, author evidence and additional source attribution. Phémios does not claim authorship or endorsement.

## Explicit account-private copies

Saving is an explicit action while authenticated. Saved copies stay on this installation in a protected native document, partitioned by the actual source, authority and stable Aède account ID. The managed local authority survives its changing loopback port. These reading copies are not synchronized to the remote Aède server. Public reference entries, Wikipedia exploration and file exports remain available independently of authentication; private copies are unavailable after logout and never appear under another account or source. The legacy unowned `phemios.encyclopedia.v1` browser document remains intact and is neither read by the desktop panel nor automatically assigned to an account.

The native store retains at most 40 articles within three MiB of UTF-8 serialized article-array bytes, excluding the response envelope. The frontend checks the same array budget before admitting a projection, so a native document exactly at its limit remains readable and removable. Each article has validated edition/page identity and bounded text; saving replaces that identity only after explicit Save. Reopening a retained page uses its copy without a public network request; Refresh explicitly requests current text, which replaces the copy only after Save. Removing a copy affects no original or editorial entry. Failed publication leaves the last confirmed file intact; unreadable documents and exhausted limits remain visible and are never repaired, evicted or overwritten implicitly.

Versioned read/update IPC carries the captured process-session ticket and actual source, never an owner identifier or filesystem path from the WebView. Native admission checks the exact generation and derives the current client identity; writes require a current user or administrator role. Auditors can read their own copies but cannot save/remove them. Mutations serialize, and queued work from a replaced account never dispatches. Projection and feedback guards discard late reads, updates and errors after account/source replacement or disposal; an account transition also clears the open reader, results and notices. Page return and edition changes separately invalidate public requests. Refresh failure leaves readable retained content in place. Shared action controls, dismissible notices, empty states and theme tokens are reused.

## System-browser source links

The desktop app intercepts explicit HTTPS anchor activations (including modifier/middle clicks) and sends them to a narrow versioned `external_open` command. The independent native policy accepts at most 4096 URL bytes, HTTPS only, no credentials, whitespace, backslashes or nonstandard ports. Fixed OS helpers receive the URL as a separate argument without shell interpretation; this is not a generic command/file opener. macOS uses `/usr/bin/open`, Linux `/usr/bin/xdg-open`, Windows the system `rundll32` URL handler. A failed immediate handoff is visible through shared dismissible feedback. Long-running handlers are reaped independently; admission does not claim that a remote page has loaded. The browser preview retains ordinary anchor navigation. These links are necessary for original references, contributor attribution, revision evidence and licence access; external content is not embedded into the application.

## Reading the corresponding language edition

The explicit switch follows `prop=langlinks` on the verified source page, restricted to the other FR/EN language and one relation. It resolves the returned title through that edition's own `titles` query with canonical redirects, requiring one main-namespace page and bounded plain text. Returned URLs are never used as request destinations. Missing relations, malformed identities, multi-page separators and section fragments fail explicitly; title search and machine translation are not fallbacks. The source text remains readable while the counterpart loads, with an activity indicator and a disabled switch. An absent/failed counterpart retains the old text and restores the switch to that text's language.

Each open reader keeps at most two verified edition texts in memory. Returning to an already opened counterpart requires no request, and Back, a new article/search, reset or disposal invalidates the pair. Copies remain explicitly saved per edition rather than synchronized or saved implicitly. Back never exposes old-edition result identities under a new language. Generation and mounted-panel guards discard late responses after return, tab replacement or disposal. First-time switching from a saved article can require network; a failed offline request preserves the saved source and reports its error.

Contract: [MediaWiki interlanguage links](https://www.mediawiki.org/wiki/API:Langlinks). Native read-only probes verify FR/EN identity round trips, including the explicitly requested public artist article; no retrieved prose is stored in the repository.

## Reference navigation and file exports

Reference categories are a flat side navigation with matching-entry counts, becoming a wrapping horizontal navigation below 900 px. Saved article rows and their removal controls share a 36 px height; long titles truncate without moving the action. A heart explicitly retains/removes the reading copy. The separate download action publishes the currently open received text, without refreshing it or implicitly retaining it.

Native exports are UTF-8 text with a BOM, edition/page identity, title, original/history/revision/licence links, retrieval date, extraction limitations and all received text. The operating system Downloads directory and generated wikipedia-{language}-{page ID}.txt names are owned by the native bridge; callers cannot select arbitrary paths. Publication validates identity, size and control characters and uses create-new collision suffixes, preserving existing files. Export is independent of Aède accounts. Duplicate actions are blocked; failed exports preserve the reader and stale completions cannot attach notices to another article.

## Artist biography reading

Biography mentions use underlined links in the surrounding text colour, including on hover, for literal, whole catalogue names. Artist identities remain unambiguous and source-qualified; genres use their existing canonical catalogue label, and track titles use only the already synchronized source projection. No article, genre alias, recording relation or unavailable track is invented. Existing artist names take precedence over a genre/title collision; ambiguous artist names remain plain text. Genre labels are not broadened to a parent category: an unavailable compound genre remains plain, rather than linking its shorter generic fragment. Unquoted single-word song names remain plain to avoid capturing ordinary prose. Explicit trailing version qualifiers such as “live” or “charity version” may supply a multiword display-title mention, while the chooser retains each complete actual track title and placement; no recording identity is merged. One matching track opens its detail; multiple distinct placements require an explicit edition choice showing retained artist/album/year/position. Opening or rendering prose starts no track download or provider enrichment, and a retired projection closes its pending chooser. Unknown or legacy track projections need an explicit synchronization before title links can be offered. These are local navigation conveniences, not reconstructed Wikipedia citation anchors; attributed text, saves and exports remain unchanged. The same policy applies to summaries and full artist/label readers. Four-digit years, including those inside full dates, link only when the combined admitted catalogue contains an owned album with that year. The year opens the existing Albums year selection, clearing stale query, country, genre, composer, recent-only and alphabet restrictions. It does not restrict results to the biography artist or infer a full release date. Missing years remain plain and catalogue changes refresh link availability; saved/exported prose is unchanged.

The edition chooser initially focuses its heading without drawing a focus outline on that non-interactive title. Tab navigation highlights each option by recolouring its existing border, keeping its geometry unchanged; Escape and closing retain focus restoration to the initiating biography link.

Aède's Wikipedia enrichment intentionally retains the REST lead summary, not the whole article. On artist and Wikipedia-sourced label pages, **Read more** explicitly resolves the attributed FR/EN `/wiki/` title through the same fixed-host public client, follows canonical redirects and validates one main-namespace page. Artist-name searches never substitute another biography. Unknown sources/languages retain their existing external attribution link. Native title admission rejects controls, fragments, multi-page separators and oversized titles before network activity. Account sessions and credentials are not involved.

The dedicated reader preserves headings, revision, retrieval date, author/history and licence links; prose remains literal text with existing source-qualified artist links. Its measure is approximately 80 characters, narrowing on smaller windows. French spacing is a presentation-only nonbreaking-space pass, leaving the received article and existing nonbreaking spaces unchanged. Up to three existing catalogue artwork kinds illustrate the text in stable order, without image enrichment on navigation, random remount changes or claims that they came from Wikipedia. Explicit Read more retains the received full text in a separate native-owned public biography cache, not in account-private saved articles. The bounded version-1 cache holds at most 40 entries / 12 MiB, keyed by edition and exact attributed title, with atomic publication and oldest-copy eviction. Reopening first displays the retained text without network and then checks only canonical identity/title/revision (`prop=info`). Full text is fetched only when absent, changed, or upgrading a legacy text-only copy with resource metadata; a failed refresh preserves the readable copy and reports dismissible feedback. The retrieval date remains the date of the retained text. Corrupt/oversized/symlink cache files are refused without implicit replacement. No key, personal annotation or account owner is stored in this public file. Source changes/disposal invalidate late replies. Long artist readers compile their source-qualified name-link index once for all paragraphs; Discogs label profiles already retain their full returned profile and are not treated as Wikipedia introductions. TextExtracts still omits tables, references and some article content; the original remains linked.

An explicit developer probe is available as `cargo run -p phemios-core --example biography_probe --locked`; it prints page/revision identities, text byte counts and section counts only. It performs public network reads and is not part of offline tests.

The summary continuation is inline at the end of prose with a separating space, before source/licence attribution. Its fixed icon slot replaces the arrow with activity. The reader's sole return action replaces the shell back destination with the artist/label; returning does not pop catalogue navigation history. Multiple received headings produce a keyboard-accessible contents list; section navigation preserves the router hash and focuses the chosen heading with clearance below the shell header. Headings and prose remain literal and repeated section names remain separate targets.

Long biography readers expose a floating Back to top arrow at the bottom-right above the player footer once their actual scroll container has moved beyond 120 px. It returns the actual scroller to zero, retaining the shell header above the reader, respects reduced motion, then returns keyboard focus to its title without changing the route. The control hides at the top and on non-overflowing readers; scoped passive scroll and size observers are released on unmount. It does not reserve prose width or alter scroll height.

The dedicated artist/label biography reader also exposes the shared download icon beside its title. It exports the entire retained Wikipedia extract through the existing account-independent `encyclopedia_export` contract, including provenance, revision, licence and retrieval date; neither typography transformations nor the introduction-only summary replace its text. Direct publication to system Downloads, without an application/category subfolder, and collision-preserving filenames apply. No network read or private saved-article mutation occurs. Browser preview disables the action; failures remain in the reader, and the common button provides activity and a temporary success check.

## External resource links

TextExtracts removes anchor addresses, including the resource providers at the end of biographies. On explicit full-text acquisition, the native client additionally calls MediaWiki `action=parse&oldid=<reported revision>&prop=text`, through the same fixed public host, public resolver, timeout, no-proxy and no-redirect policy. Both returned page ID and revision must match the validated extract identity before links are admitted. Scraper 0.27.0 (ISC, default features disabled) parses that bounded HTML in Rust. It never executes scripts or loads styles, media or resource addresses. HTML is transient and does not cross IPC or enter saved documents.

Only labelled external anchors inside the FR/EN external-links section are retained, in source order. Navigation/metadata/edit controls are excluded. Repeated label/address pairs are deduplicated; identical labels with distinct addresses are preserved. The optional `externalLinks` array carries only label and URL, with at most 256 pairs and 128 KiB serialized metadata. Labels are bounded to 512 UTF-16 code units; HTTP(S) addresses are bounded ASCII public-style destinations without credentials, active schemes, private literals or local hostnames. These checks also apply to native private storage/restore and frontend parsing. No provider link is fetched automatically.

Readers link literal labels only inside their external-links prose. Each occurrence consumes one source pair; unmatched labels remain available in a separate explicit resource list, rather than guessing another URL or dropping a link. Existing source-qualified artist mentions remain available in other text. Account-private copies, personal backup and text download retain the labelled addresses. An exact saved-copy comparison includes this metadata, so a refreshed copy can be saved even when its article revision/text is unchanged.

Old documents remain readable with no automatic private migration or network request. On explicit biography reopen, an old public cache entry is upgraded once; subsequent unchanged reopens check only identity/revision. A previously saved article requires Refresh and then Save to retain its newly recovered links. An enrichment failure leaves previous bytes intact and uses the existing visible reader diagnostic.

Verification: 17 encyclopedia/cache/parser Rust cases, five private-article cases and five personal-backup cases pass, along with 1041 frontend tests and 25 Node tests, App/Storybook TypeScript, lint and core Clippy. A temporary offline probe against an actual public Ozzy Osbourne API response validated 56 extracted external resources, including AllMusic and MusicBrainz; no prose was added to the repository. The Storybook resource scenario is typechecked, not browser-executed. No Tauri/site/Storybook application build or commit is performed.

Legacy HTTP resource addresses are handed to the same explicit system-browser command as HTTPS links rather than falling through to WebView navigation. The OS helper still receives one validated URL argument without a shell; only standard HTTP/HTTPS schemes/ports without credentials are admitted, and new HTTP destinations additionally use the public-feed address policy. This does not change the HTTPS/WSS transport for Aède or perform an HTTP resource fetch inside Phémios. A regression first reproduced the prior missing HTTP interception; frontend and native handoff tests cover the extension.

## Resource security and persistence follow-up

Two demonstrated defect groups are corrected. First, resource admission used different URL semantics from the browser: native validation admitted `https://0x7f.1/` (normalized by the browser to loopback) and an IPv4-mapped IPv6 literal that the frontend refused. Both readers also admitted cross-scheme ports such as HTTP:443 that the native handoff rejected. A failing native case records the admitted inputs; a frontend regression records the accepted-but-unopenable ports. The approved direct use of already locked `url` 2.5.8 now validates normalized native hosts, including the HTTP browser handoff. Resource metadata admits only bounded DNS destinations, refuses local/localhost suffixes and literal IPs, and uses the handoff's scheme/port policy. A shared JSON matrix covers 31 representative valid/invalid addresses in native and frontend tests, including uppercase schemes, trailing dots and a valid IDN A-label. No additional registry package or version change is introduced by declaring url directly.

Second, literal matching consumed a provider label inside another word: `Archive` in `TheArchiveMuseum` acquired the resource URL and deprived a later standalone `Archive` of its link. A failing frontend test reproduces this. Matching now skips occurrences touching Unicode letters, numbers, combining marks or underscores and continues looking for the actual label. Source order, separate repeated labels and unmatched-resource fallback remain unchanged.

Additional passing cases confirm that a refused refresh leaves public-cache bytes/text/links unchanged, refused resource replacement preserves the private saved copy, and a delayed save failure cannot publish another account's resource diagnostics. Existing legacy-cache upgrade, backup restoration, exact revision, bounded HTML extraction and saved-copy tests pass. No new defect is demonstrated in those inspected persistence/ownership paths. A provisional invalid-IDN hypothesis was discarded rather than reported: the browser runtime and native IDNA implementation did not classify that synthetic name identically; it is not included in the shared conformance claim. Validation is syntactic admission, not a DNS or provider-trust guarantee; links are not fetched automatically and user-activated redirects remain the system browser's responsibility.

All 1045 frontend tests across 226 files and 25 Node tests pass, with 33 targeted Rust cases for Encyclopedia/cache, private articles, backup and browser handoff. App/Storybook TypeScript, lint, core Clippy, Rustfmt, touched-file formatting and diff checks pass. No live account mutation, new provider read, Tauri application/site/Storybook rebuild or commit belongs to this follow-up.

## Excluded-section and authority confirmation

Two further demonstrated defect groups are corrected. Headings inside excluded navigation/metadata blocks could open or close resource-section extraction: an unrelated link was retained and a legitimate later resource was lost. Section changes now exclude both the heading itself and its ancestors; external anchors apply the same rule. The regression covers nested navigation, nested metadata, directly classified headings/anchors and the actual following section.

The frontend also admitted empty user-info authorities (`https://@music.example/` and `https://:@music.example/`) that the native handoff refused. Authority admission now rejects any raw `@`, while preserving `@` in paths and fragments. The shared native/frontend address matrix grows from 31 to 35 inputs.

Inspection of neighboring cache, private article validation, restore and owner-scoped completion paths establishes no additional defect in this pass. This is a bounded code and regression review, without live account mutation or provider requests. Existing cache-preservation and private-store cases remain passing.

Verification: 21 encyclopedia/cache/parser, six private-article, five personal-backup and two browser-handoff Rust cases pass; 1045 frontend tests across 226 files and 25 Node tests pass. App/Storybook TypeScript, lint, core Clippy, formatting and diff checks pass. No App, site or Storybook rebuild and no commit are performed.
