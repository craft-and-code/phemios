# Encyclopedia contracts

## Local reference and explicit public exploration

The existing 25 original bilingual reference entries remain bundled, attributed and available without an account or network. Their category/text search is unchanged. Separate Wikipedia and Saved articles tabs distinguish external text from project editorial content. The compact sliding FR/EN switch shares the top toolbar at its right edge; click/Space toggles its edition and Left/Right chooses FR/EN; choosing an edition does not change the application language. Reference cards, search rows and the reader use the same accent hover border as artwork. Choosing a tab or reopening a saved article never fetches content. Explicit edition switching follows the current article rather than returning to an empty form; switching an existing search repeats its current query in the chosen edition. The Wikipedia search form is explicit, has a 200-character limit, and returns at most twenty main-namespace titles. Queries are sent to the selected French or English Wikipedia edition; they never include Aède identity or credentials.

`core::encyclopedia` owns a fixed-host HTTPS MediaWiki Action API client, independent of Tauri and Aède sessions. `src-tauri::encyclopedia` exposes only versioned search(language, query), article(language, page ID), and translate(source language, source page ID, target language) commands, with a single bounded active-request gate. Hostnames are constructed from the two permitted languages, public DNS policy is reused, redirects/proxies are disabled, the descriptive User-Agent links to the related Aède project site, requests have a 15-second deadline and responses are capped at one MiB. Search snippets are not requested or interpreted. IDs, namespace, page count, revision and text are validated before returning typed projections; the frontend validates again. Service errors, empty/missing extracts, limits and network failures are visible, not replaced with invented reference content. Browser preview has no external request capability.

## Reading and attribution

Article reading uses `prop=extracts|info`, `explaintext=1`, `exsectionformat=wiki`. TextExtracts is a stable read API with known extraction limitations and no active new-feature maintenance. It provides text rather than a complete rendering: images, tables and some references are omitted. The reader labels this limitation and links to the original. Heading markers become semantic local headings, and all other content is literal Solid text; no remote HTML, scripts, styles or media are loaded. Text has a 512 KiB native limit. No article text is bundled into the product or tests from Wikipedia.

Each copy retains edition, page ID, title, full received text, revision reported by the same query, and retrieval timestamp. Attribution links are built locally from validated identifiers: current article, reported revision, author/history page, and CC BY-SA 4.0 licence. The API extract is not a byte-for-byte historical revision export; extraction can omit material and reflect service caching. Consult the original revision/history for complete wording, author evidence and additional source attribution. Phémios does not claim authorship or endorsement.

## Explicit account-private copies

Saving is an explicit action while authenticated. Saved copies stay on this installation in a protected native document, partitioned by the actual source, authority and stable Aède account ID. The managed local authority survives its changing loopback port. These reading copies are not synchronized to the remote Aède server. Public reference entries, Wikipedia exploration and file exports remain available independently of authentication; private copies are unavailable after logout and never appear under another account or source. The legacy unowned `phemios.encyclopedia.v1` browser document remains intact and is neither read by the desktop panel nor automatically assigned to an account.

The native store retains at most 40 articles within three MiB of UTF-8 serialized article-array bytes, excluding the response envelope. The frontend checks the same array budget before admitting a projection, so a native document exactly at its limit remains readable and removable. Each article has validated edition/page identity and bounded text; saving replaces that identity only after explicit Save. Reopening a retained page uses its copy without a public network request; Refresh explicitly requests current text, which replaces the copy only after Save. Removing a copy affects no original or editorial entry. Failed publication leaves the last confirmed file intact; unreadable documents and exhausted limits remain visible and are never repaired, evicted or overwritten implicitly.

Versioned read/update IPC carries the captured process-session ticket and actual source, never an owner identifier or filesystem path from the WebView. Native admission checks the exact generation and derives the current client identity; writes require a current user or administrator role. Auditors can read their own copies but cannot save/remove them. Mutations serialize, and queued work from a replaced account never dispatches. Projection and feedback guards discard late reads, updates and errors after account/source replacement or disposal; an account transition also clears the open reader, results and notices. Page return and edition changes separately invalidate public requests. Refresh failure leaves readable retained content in place. Shared action controls, dismissible notices, empty states and theme tokens are reused.

## Verification and sources

Behavioural tests cover identity/namespace/size checks, literal markup, adjacent headings, edition separation, copy replacement, corrupt and failed stores, quota limits including the exact native byte boundary, explicit network actions, duplicate requests, late results/errors, logout/source/account isolation, refused auditor writes, invalidated queued mutations and offline reopening. `cargo run -p phemios-core --example encyclopedia_probe --locked` explicitly probes the real French and English service without recording article prose or credentials. Normal tests are offline.

Primary contracts: [MediaWiki search](https://www.mediawiki.org/wiki/API:Search), [TextExtracts](https://www.mediawiki.org/wiki/Extension:TextExtracts), [Wikimedia Terms of Use](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use), [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/), [Wikimedia User-Agent policy](https://foundation.wikimedia.org/wiki/Policy:Wikimedia_Foundation_User-Agent_Policy).

## System-browser source links

The desktop app intercepts explicit HTTPS anchor activations (including modifier/middle clicks) and sends them to a narrow versioned `external_open` command. The independent native policy accepts at most 4096 URL bytes, HTTPS only, no credentials, whitespace, backslashes or nonstandard ports. Fixed OS helpers receive the URL as a separate argument without shell interpretation; this is not a generic command/file opener. macOS uses `/usr/bin/open`, Linux `/usr/bin/xdg-open`, Windows the system `rundll32` URL handler. A failed immediate handoff is visible through shared dismissible feedback. Long-running handlers are reaped independently; admission does not claim that a remote page has loaded. The browser preview retains ordinary anchor navigation. These links are necessary for original references, contributor attribution, revision evidence and licence access; external content is not embedded into the application.

## Reading the corresponding language edition

The explicit switch follows `prop=langlinks` on the verified source page, restricted to the other FR/EN language and one relation. It resolves the returned title through that edition's own `titles` query with canonical redirects, requiring one main-namespace page and bounded plain text. Returned URLs are never used as request destinations. Missing relations, malformed identities, multi-page separators and section fragments fail explicitly; title search and machine translation are not fallbacks. The source text remains readable while the counterpart loads, with an activity indicator and a disabled switch. An absent/failed counterpart retains the old text and restores the switch to that text's language.

Each open reader keeps at most two verified edition texts in memory. Returning to an already opened counterpart requires no request, and Back, a new article/search, reset or disposal invalidates the pair. Copies remain explicitly saved per edition rather than synchronized or saved implicitly. Back never exposes old-edition result identities under a new language. Generation and mounted-panel guards discard late responses after return, tab replacement or disposal. First-time switching from a saved article can require network; a failed offline request preserves the saved source and reports its error.

Contract: [MediaWiki interlanguage links](https://www.mediawiki.org/wiki/API:Langlinks). Native read-only probes verify FR/EN identity round trips, including the explicitly requested public artist article; no retrieved prose is stored in the repository.

## Reference navigation and file exports

Reference categories are a flat side navigation with matching-entry counts, becoming a wrapping horizontal navigation below 900 px. Saved article rows and their removal controls share a 36 px height; long titles truncate without moving the action. A heart explicitly retains/removes the reading copy. The separate download action publishes the currently open received text, without refreshing it or implicitly retaining it.

Native exports are UTF-8 text with a BOM, edition/page identity, title, original/history/revision/licence links, retrieval date, extraction limitations and all received text. The fixed Downloads/Phémios/Encyclopédie directory and generated wikipedia-{language}-{page ID}.txt names are owned by the native bridge; callers cannot select arbitrary paths. Publication validates identity, size and control characters and uses create-new collision suffixes, preserving existing files. Export is independent of Aède accounts. Duplicate actions are blocked; failed exports preserve the reader and stale completions cannot attach notices to another article.

## Artist biography reading

Aède's Wikipedia enrichment intentionally retains the REST lead summary, not the whole article. On artist and Wikipedia-sourced label pages, **Read more** explicitly resolves the attributed FR/EN `/wiki/` title through the same fixed-host public client, follows canonical redirects and validates one main-namespace page. Artist-name searches never substitute another biography. Unknown sources/languages retain their existing external attribution link. Native title admission rejects controls, fragments, multi-page separators and oversized titles before network activity. Account sessions and credentials are not involved.

The dedicated reader preserves headings, revision, retrieval date, author/history and licence links; prose remains literal text with existing source-qualified artist links. Its measure is approximately 80 characters, narrowing on smaller windows. French spacing is a presentation-only nonbreaking-space pass, leaving the received article and existing nonbreaking spaces unchanged. Up to three existing catalogue artwork kinds illustrate the text in stable order, without image enrichment on navigation, random remount changes or claims that they came from Wikipedia. Explicit Read more retains the received full text in a separate native-owned public biography cache, not in account-private saved articles. The bounded version-1 cache holds at most 40 entries / 12 MiB, keyed by edition and exact attributed title, with atomic publication and oldest-copy eviction. Reopening first displays the retained text without network and then checks only canonical identity/title/revision (`prop=info`). Full text is fetched only when absent or changed; a failed refresh preserves the readable copy and reports dismissible feedback. The retrieval date remains the date of the retained text. Corrupt/oversized/symlink cache files are refused without implicit replacement. No key, personal annotation or account owner is stored in this public file. Source changes/disposal invalidate late replies. Long artist readers compile their source-qualified name-link index once for all paragraphs; Discogs label profiles already retain their full returned profile and are not treated as Wikipedia introductions. TextExtracts still omits tables, references and some article content; the original remains linked.

An explicit developer probe is available as `cargo run -p phemios-core --example biography_probe --locked`; it prints page/revision identities, text byte counts and section counts only. It performs public network reads and is not part of offline tests.

The summary continuation is inline at the end of prose with a separating space, before source/licence attribution. Its fixed icon slot replaces the arrow with activity. The reader's sole return action replaces the shell back destination with the artist/label; returning does not pop catalogue navigation history. Multiple received headings produce a keyboard-accessible contents list; section navigation preserves the router hash and focuses the chosen heading with clearance below the shell header. Headings and prose remain literal and repeated section names remain separate targets.

Long biography readers expose a floating Back to top arrow at the bottom-right above the player footer once their actual scroll container has moved beyond 120 px. It returns the actual scroller to zero, retaining the shell header above the reader, respects reduced motion, then returns keyboard focus to its title without changing the route. The control hides at the top and on non-overflowing readers; scoped passive scroll and size observers are released on unmount. It does not reserve prose width or alter scroll height.
