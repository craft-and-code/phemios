# Native Aède integration

## Boundary

Aède owns catalog references, account authorization, annotations, query grammar, playlist ordering, media jobs and file/path rules. Phémios has a framework-independent HTTP/cache client and narrow versioned Tauri commands; all frontend IPC lives in `src/platform/desktop.ts`. Authentication returns public account metadata only. The password is discarded; the bearer token is process-only. Explicit local loopback HTTP or remote HTTPS is accepted, never redirects, URL credentials or arbitrary request authorities.

The client bounds request JSON (16 KiB), each JSON response (16 MiB), total cached public catalog (100 MiB), artwork (32 MiB) and request time (30 seconds). Complete presentation pagination validates totals/offsets/progress and requires one scan epoch. Snapshot DTO validation preserves unknown origin/year, compilations without a principal artist, contributor references and biography attribution. Missing projected services are errors, never fabricated demo data.

## Additive server contracts

- `GET /api/v1/presentation/artists` and `/albums`: paged public presentation fields, all raw tag fields/values for local search, sourced origin/biography, available artist media, release credits and local collaboration neighbours.
- `GET /api/v1/artwork?ref=...&kind=cover|portrait|banner|background|spectrum`: confined entity-owned binary images, bounded rendering, ordinary bearer authorization. No arbitrary filesystem path or external enrichment URL. A missing/symlink/oversize file is not advertised as available.
- `GET /api/v1/analysis/report?ref=TRACK_OR_RELEASE`: original-format scoped FlacCompagnon report, reconstructed from complete retained source entries, with no analysis/file mutation. Missing/stale/incomplete data is an error. Native Downloads publication validates the wrapper and limits, preserves unknown fields and selects its own filename; repeated downloads do not overwrite files.
- Existing read-only `/api/v1/stats` and `/api/v1/doctor`: whole-library measurements, bounded breakdown/ranking pages and saved integrity/analysis diagnostics. The client validates numeric ranges, page windows and scan epochs; tables at the same offset share one request. Opening Statistics does not start checks, analyses or enrichment. Offline statistics display public snapshot counts and coverage, with server-only measures explicitly unavailable. Current-owner values remain a separate memory-scoped section.
- Existing `/api/v1/album`, `/track`: track references, file analyses with provenance, and additive `spectrum_available` on track details.
- `GET /api/me/v1/annotations`: paged current-owner annotations. Existing singular annotation/collection and paged collection/history endpoints remain authoritative.
- `POST /api/me/v1/m3u`: save an album's ordered tracks as a private static playlist and an atomic server file. `GET` lists summaries; `GET /{id}` provides owner-scoped download content. M3U uses server paths and does not assume a remote client has those paths.
- `POST /api/admin/v1/analyze` or `/spectrum`: catalog release reference, explicit force option, bounded threads. Aède resolves the release folder and uses its cancellable job manager; no user-supplied arbitrary path. Existing task status/cancel endpoints supply bounded output. Requires a local administrator.

See Aède's bilingual server presentation documentation for exact responses and limits. Native bridge version 1 is unchanged because these commands are additive.

## Artwork lifecycle and responsive navigation

Catalog and image cache paths are application-owned, never supplied by the webview. Image keys include server, account, catalog scan version, entity and media kind. Atomic writes and bounded reads distinguish missing data from corruption. Public cache never includes credentials or private annotations. Corrupt catalog data is preserved; explicit synchronization can replace disposable cache data.

After owner annotations load, one worker warms available covers, portraits, banners and backgrounds. One inspection slot remains available for navigation. Transient HTTP 429/503 read admission is retried at most four times with bounded exponential waits (150, 300, 600, 1200 ms); permanent errors and mutations are not retried. A visible failure count distinguishes attempts from successful loads. Resident blob URLs are shared by all views; card mount, density changes and scrolling do not request covers. Reloading the native app reads the disk cache without authenticating. New scan epochs invalidate old image namespaces; repeated synchronization of an unchanged catalog reuses images. Existing-media replacement requires a rescan. Old namespaces currently accumulate: quota/pruning and bounded decoded-memory working sets remain acceptance work. Missing media has a stable square and an explicit reason rather than an invented cover.

Search normalizes supplied metadata and current-owner values, with immutable weak indexes connecting principal and credited artists to releases. Albumless artists have an explicit unknown-year policy. A 10,000-artist fictional behavior test validates associations; it is not a rendered-scroll benchmark or proof that every cold cover can appear instantaneously.

## Personal actions and analysis

Artist and album stars/favourites save immediately as single-field patches through the existing annotation PUT contract. Rapid activations are serialized in click order. Notes and tags remain a separate explicit draft; icon changes never publish or replace that draft, and saving the draft never overwrites stars/favourites. Failed icon writes roll back the latest affected control to the last confirmed value and report the failure; mutations are not retried automatically. Late results and queued work cannot cross a session change. Milkdown displays formatting directly with a local icon toolbar. Untouched Markdown is preserved byte-for-byte when changing other annotation fields; parser normalization is not a user edit. Links and images render inert text/marks rather than fetching remote resources. The editor loads only on detail pages and is destroyed on navigation. Editor failure preserves the source note and disables saving, preventing silent loss. Save errors retain the draft; account changes clear the in-memory annotation map. The server owns privacy and roles. Favourites show directly loved albums and principal albums of loved artists in one cover grid. Collections create or replace validated smart-query rules; saved rules can be evaluated as current album grids; arbitrary manual collections remain separate work. History displays only server-confirmed records, with unavailable track diagnostics. Personal page reads validate responses and resolve failures explicitly instead of throwing into the navigation shell.

M3U generation stores on Aède before enabling download. Native download fetches the current-owner playlist again and writes exact server content under the OS Downloads directory, in `Phémios/`. IDs/content are validated; a client filename/path is never trusted, and repeated downloads choose a new filename instead of replacing existing bytes. No general filesystem plugin is exposed. Explicitly started media tasks are retained across page navigation, scoped to the chosen release, polled while connected and cancellable. Opening an album only reads already available results. Completed tasks refresh track details; a spectrum image is loaded on its explicit track-icon toggle and reused when reopening. Analysis/spectrum jobs may publish sidecars beside the chosen album: acceptance uses an isolated audio copy, never the user's original library.

The discovery graph displays at most 16 local collaboration neighbours, ordered by shared-track weight. Keyboard and list alternatives remain available. Collaboration is not band membership; this first contract does not expose dated external membership or its roles. No external query runs from discovery navigation.

## Module boundaries and limits

`core/src/network.rs` retains one cohesive bounded authenticated client (~327 lines); transport, authority validation and allowlist belong to that boundary. `src/library/context.tsx` keeps the shared session/catalog/annotation/media lifecycle (~276 lines). `App.tsx` holds route/filter composition (~327 lines). `PersonalPage.tsx` keeps current-owner paged views and explicit mutations (~274 lines). `StatisticsPage.tsx` keeps one coherent composition of server totals, metadata coverage, local media and owner summaries (~336 lines); parsing and independently paged tables have separate modules. These are modest exceptions to the usual 250-line guideline, with separate policy/test modules; split them when independently evolving services justify it.

Synchronized lyrics, consumed-signal visualization, repeat/shuffle and mounted-device conversion/verification/copy are not connected by this milestone. Their disabled controls are intentional. Catalog event synchronization, minimum Rust/other-platform builds, cache quotas, virtualization and sustained fast-scroll measurements remain pending. Native visual acceptance now includes authenticated real-library synchronization and binary-image IPC. Final cache, album and download checks are recorded in the acceptance log.

## Connection indicator

The toolbar shows a red blinking dot without a verified connection and a green heartbeat while connected. Reduced-motion preferences disable both animations. After explicit native login, a serialized read of the existing authenticated `GET /api/auth/v1/session` runs every 15 seconds after the previous probe completes. Failure turns the indicator red without erasing the session, cached library or draft; a later successful probe restores green. Native transport timeout remains 30 seconds. Polling stops on logout/unmount and never starts during offline browsing. An expired/revoked session needs explicit login again.

Tag autocomplete uses the current-owner annotation map already loaded through paging; it adds no endpoint or persistent vocabulary. Enter/comma create tokens, and explicit note/tag save includes unfinished text. Failed writes retain the draft. Display changes preserve the existing analysis export/native publication contracts.

## Native PCM playback

The approved CPAL, rtrb and tungstenite dependencies add a framework-independent audio actor. Explicit album/track playback sends an ordered logical selection of at most 4096 catalog track references through versioned native IPC. Each WebSocket start contains one track within the unchanged 64-occurrence wire limit. Starting a particular track retains the album's complete order and selected index. Native credentials authenticate the fixed `/api/me/v1/playback` WS/WSS route; bearer tokens and PCM never enter the WebView. HTTPS uses system-trusted roots and certificate validation. Native output discovery runs only on request. The selected/default CPAL output's mono/stereo format and rate determine the processed f32le stream requested from Aède, with normalization off and flat tone; this remote route does not claim original-rate or bit-perfect output.

A bounded half-second ring feeds the callback without locks, allocations, disk or network I/O. Only popped source frames advance consumption; paused or underrun silence does not. Native acknowledgements and the displayed clock follow that consumption. Volume is process-only linear gain from zero to one, initially 0.5. Rapid UI volume changes coalesce while preserving the final value. Unavailable/unsupported devices, invalid PCM, source failures and stalled consumption fail visibly rather than selecting another device silently. DNS resolution follows the OS resolver; TCP attempts, handshake, socket I/O and stalled-stream deadlines are bounded separately.

Play/pause, previous/next, stop, seeking and output selection are connected. Previous restarts the current track after three seconds, otherwise moves backward. Pause suspends the device, stops the socket with the consumed-frame count and waits for Aède's saved confirmation. Resume opens a new visit and seeks to the retained source offset before enabling consumption; prefetched old-epoch PCM is discarded. Seek/output changes similarly reopen the stream, preserving pause. Natural completion advances the ordered selection. These per-track connections do not promise gapless joins. Aède owns history publication; Phémios waits for server confirmations and never sends a duplicate history POST. Each resumed connection is a separate incomplete visit under the existing server contract. Missing saved-history confirmation reports uncertainty. Logout stops and joins playback before session revocation; quitting requests best-effort stop. A new login never autoplays or restores a private queue.

Repeat/shuffle, synchronized lyrics, consumed-signal effects and external-player copying remain separate work. Native macOS execution verifies host wiring and actual callback consumption; other-platform execution and digital-output capture remain unverified.

## Dynamic collections and contextual playback

Catalog filter collection creation freezes the criteria at opening, not the result. It sends a versioned `browse-v1:` query to the existing owner-scoped store with `create_only`, so name collisions never overwrite a rule. Aède evaluates current years, initials, unknown years, origin union, genre, compilation view and all-field search against the current catalog/trusted claims/own annotations. Collection covers come from the current-owner album-reference evaluator; missing cached editions produce a resynchronization error. Plain query editing remains available; browsing criteria currently require creating a replacement collection from the catalog filters.

History reset sends one explicitly confirmed DELETE with a JSON body; it is never retried. Aède clears the current owner's events, scrobbles and counters together, preserving annotations, collections and checkpoints. Active playback can create later events.

Idle footer Play starts the visible album or principal artist discography returned by Aède's shared chronological ordering contract. A local logical selection is bounded at 4096 entries; each PCM connection still starts one track, within the unchanged server 4 KiB/64-occurrence wire budget. The current metadata is addressed by logical index, with the server's per-album position/total, and the footer cover links to that edition. Pause/resume retain the active selection independently of page navigation.

Mute preserves the latest audible app gain and toggles zero without altering the consumption clock. Countdown preference is sessionStorage scoped by server/account identity, cleared from active state on logout and recovered on later identification in the same webview session. It is neither an authentication secret nor a server-synchronized preference. Audio settings use a dedicated icon; refresh discovers native outputs only on explicit request.

DSP requests Aède album normalization; without-effects requests normalization off and flat bass/treble. Mode changes checkpoint/stop the current stream and reopen at consumed position, retaining pause. Aède owns DSP implementation. Neither mode guarantees bit-perfect: source/output format adaptation, f32 transport, local gain and host mixing remain independent limitations. The third mode is displayed unavailable and also rejected by the native boundary; no silent fallback exists.

## Ordered disc pages and server capability checks

`GET /api/v1/presentation/tracks` pages lightweight album-order rows (50 per client request, 4096 logical-entry bound), validates one scan epoch, total/offset/positions and distinct references, and retains nullable disc/track numbers. Same-title placements are not deduplicated. Only explicit expansion reads complete retained analyses from `/api/v1/track`; source audio is never opened by client browsing. Album report availability uses the server's light analysis-presence flags, while export still rechecks completeness/staleness on Aède.

Filter collection creation first reads `/api/v1/status` and requires `dynamic_browse_collections`. Older processes fail with a specific update/restart explanation before any PUT. Late capability checks cannot publish to a replacement account/session. The Rust boundary reads at most 8 KiB of error JSON and translates known codes; it never echoes arbitrary response messages. Unknown routes, missing entities, name collisions and busy stores remain distinct.

## Track navigation and recent additions

All-track pages use authenticated `/api/v1/presentation/tracks` without a release, with server-side `q`, fifty lightweight rows and snapshot-epoch checks. Catalog track placements retain nullable editions and disc positions; detail uses `/api/v1/track` for file properties, raw tags and attributed personnel credits. Notes/ratings/favourites retain the existing track-scoped personal annotation contract. A single track can start native playback without inventing an album for an albumless title. Return navigation uses the existing history policy.

Recent additions use Aède's optional first-observed `added_at`, with an inclusive rolling thirty-day window and newest-first ordering. Legacy unknown dates remain excluded and explicitly counted. Neither release year nor file modification time is a substitute. No frontend date inference or scan runs on page opening.

Relations can switch between proven artist collaborations and catalog-associated release editions. Artist nodes preserve shared-track counts/provenance; album edges indicate association only, never an inferred shared performance. Up to sixteen spheres use explicit depth/radial gradient palettes; names remain visible and leaders highlight with their node. Album nodes and cover grids open ordinary album detail through the existing delegated navigation policy.

## Consumed-sample level indicators

Four compact bars report left RMS, left peak, right RMS and right peak from the PCM frames actually consumed by the CPAL callback. Their block measurements include underrun silence and precede the local volume gain, so muting does not fabricate a stop. They are amplitude meters, not four spectral bands. Work is bounded to each output block, with fixed accumulators and relaxed atomics; no callback allocation, lock, network request or logging is introduced. Snapshot levels are zero outside active, unpaused playback. Display follows only the current stable track reference in album/all-track rows, the artist's current-track strip and the footer. Height transitions respect reduced motion; there is no free-running animation.

Spectrum downloads request `/api/v1/artwork` without `size`, so the exported file keeps the retained image's original dimensions; resident previews may still be resized. The native export preserves the authenticated response bytes and publishes only confined, private, collision-safe PNG/JPEG paths. Track-list paging belongs to the shell so opening and returning from a detail retains the selected fifty-row window; a changed query or session resets it.

The relation graph's focused exception to the usual module-size guideline keeps the SVG layers, accessible node actions, labels and one pointer/keyboard rotation state together. Its geometry and palette policies remain separately testable in `relation-space.ts`.

## Folder publication and playback presentation follow-up

The album M3U icon checks `library_m3u_publication` and explicitly requests `library:true`. This shared-library operation requires a local administrator; Aède derives album/complete artist destinations from the same folder planner as its CLI and returns `library_files`. The client displays confirmation to the left of actions and exposes destinations in its tooltip. Downloads remain private server-path exports. A saved matching private selection is reused rather than duplicated; missing exports are recreated. No mutation is retried automatically.

The visible four bars now use FlacCompagnon's output-RMS policy: actual mono/stereo written samples after app gain, RMS multiplied by four and clamped, then response coefficients 0.14/0.45/0.24/0.56, 3–12 px heights, 2 px widths and 80 ms transitions. Active snapshots use a serialized 60 ms cadence instead of 250 ms; there are no random values or keyframes. The centred alignment remains specific to Phémios. Paused/connecting rows reserve the same 14 × 12 px slot with four flat lines. Retained stereo RMS/peak fields remain backward compatible but do not drive this decoration. Host output latency and acoustic timing still require their own measurement.

Seek drag previews are separate from consumed time and survive clock polls. A queued seek returns an opaque native ticket; the actor exposes its applied ticket with the new position. The committed cursor stays put until that acknowledgement arrives, and rapid pending choices retain the latest target. Logout/reference changes clear previews and stale results. No chosen seek position is submitted as played duration. The single-track page initially opens available retained analyses/spectrum, while album/all-track rows remain collapsed. File facts use decimal French size units and the same rounded minute/second convention as FlacCompagnon.

The audio facade keeps command admission, shared public state and actor ownership together as a coherent module-size exception. The frontend player similarly keeps queue/session lifecycle and its serialized polling together; seek preview/coalescing policy is isolated in `seek-progress.ts` rather than adding DOM rules to the native actor.

## Detail reading and explicit editing

Artist, album and track personal tags/Markdown notes open in reading mode. The pencil opens the existing Milkdown/tag draft; Save closes it only after Aède confirms the write, while Cancel restores the last confirmed text. Stars and favourites remain immediate independent patches. Reading uses the same inert link/image schema as editing and does not fetch note media. The native system window title uses `Phḗmios`; system title-bar typography stays platform-owned.
