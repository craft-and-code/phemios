# Saved collections in navigation

An authenticated user adds existing private Aède collections in **Settings → Navigation**. Collections appear to the right of menus, below them at narrow widths. The shared multiple-selection list supports Shift-click, Shift+arrows/Home/End, Ctrl/Command-click, additive Ctrl/Command+Shift ranges and Ctrl+A/Command+A. An anchored range can shrink or reverse without losing its initial anchor; focus is distinct from the first selected row. Add or Enter creates all selected shortcuts in directory order with one persisted update, respecting the existing item/byte budgets; refusal preserves the complete previous menu and selection. Selected rows use immutable collection IDs so a rename retains selection and delete/recreate cannot adopt it. Double-click selects/activates its row; dragging operates on one row, dropping on a menu row inserts before it, and dropping in the empty tail appends. A presentation shortcut never copies a rule. Removing a shortcut or resetting navigation retains the actual collections.

## Stable identity and one canonical name

Format-3 personal stores require an Aède build containing stable collection identities. An older engine may still answer public catalogue reads while rejecting private reads, producing errors across otherwise unrelated views. A compatibility failure must preserve all personal data; rescanning or resetting preferences is not a downgrade procedure. Native preparation still selects the latest published stable source. Until the identity change is published, an explicitly identified local QA engine is required for stores already upgraded by that candidate; the stable 0.7.3 source does not contain the unpublished identity change.

A shortcut keeps its opaque UUID (`collection:UUID`) for route/history stability and separately targets Aède's immutable collection ID. `#/collection/UUID` contains neither private name nor expression. All album evaluation uses the ID within the captured account/source. Delete/recreate never rebinds an ID to a new collection with the old name. Unavailable or foreign shortcuts remain explicit rather than selecting a guessed target.

The collection owns the name. Renaming a collection from Collections or its menu pencil uses the same atomic owner-scoped PATCH by ID; all shortcuts to it follow the confirmed canonical name. Collision and authorization failures preserve the name/rule. An auditor can add presentation shortcuts but cannot rename collections. Ordinary section/heading labels remain independently editable. An unnamed spacer displays neither text nor a menu icon. Its pencil accepts an optional group title; a named spacer uses the same uppercase presentation as built-in headings. Clearing the title restores blank space. Named spacers retain their position, visibility and removal controls. Headings have neither an icon nor an empty icon slot; group names begin in the menu icon lane, and actual menus retain their icons.

The picker has no initial alias input or permanent refresh button. A bounded owner-scoped directory is read on login/source replacement, reentering Navigation, returning focus and successful in-app renames. Retry appears only after an error. Late answers are retired on owner/source replacement or disposal. Reads validate all 50-row pages up to 4096 rows, stable scan epoch/count and unique names/IDs. They are not a transactional snapshot if another client changes a collection between pages without changing the epoch/count. No timer polling or metadata enrichment is introduced.

An older Aède without ID-bearing views produces an explicit update/restart message. ID-based renames require `collection_identity`; unsupported operations never fall back to guessing by name. Publishing this feature requires a published compatible Aède engine, including its personal-store format-3 migration; the ordinary native build still selects the latest stable release. A local candidate App may be built for QA with explicit provenance and a temporary build-hook configuration, never relabelled as a published release.

## Preferences and migration

Menu schema 9 adds optional `labels[separator]` group titles to schema 8's immutable collection targets. Clearing a spacer name removes its label entry; removing the spacer also removes its label and hidden entry. Versions 1–8 preserve order, visibility and ordinary labels. Schema 8 retains `collections[shortcut]` as a cached canonical label and adds `collectionIds[shortcut]` for immutable targets. Version-7 name-based shortcuts bind once, only to an exact current-owner directory name, and discard their old independent alias after successful binding. A missing old name stays unresolved; there is no fuzzy or cross-owner inference. Because version 7 had no stable target, a deletion/recreation before this one-time migration cannot be distinguished; remove/re-add that legacy shortcut if its provenance is uncertain. Once bound, it never follows a reused name. ID-bound labels always use the canonical collection name.

The established 96-item and 8192-character budgets remain. Invalid IDs, orphan references, malformed records and storage failures preserve retained bytes and confirmed navigation. A failed migration remains visible through the menu preference error. Shortcuts remain in existing per-account/source synchronization and explicit portable backup. Older Phémios versions reject schema 9; downgrade requires a prior backup or explicit navigation reset. No background migration renames the server's collection.

## Album catalog

The Collections manager has a reverse-order button immediately before Create. It reverses the filtered names on the current 50-row page without another directory read or collection evaluation; pagination remains owned by Aède. Favorites keep their independent order control. Opening a collection, rather than reversing the directory, acquires its album results.

The **album catalog** is the shared presentation for Albums and pinned collections: one shell header provides filter rails, result counts, recent additions, cover size, reverse order and explicit list/grid/Cover Flow choices. The grid button sits between List and Cover Flow; List and Grid enable cover sizing, while Cover Flow keeps its independent responsive size. List artwork follows the chosen pixel size up to 35% of its row width, preserving room for titles and playback actions in narrow windows. `AlbumCatalog` reuses `LibraryPage` for artwork, playback actions and listening markers. Albums, Compilations, Composers and each pinned menu keep independent presentation choices in session memory; Compilations defaults to a grid and supports Cover Flow. Each pinned menu retains its own in-memory filters, separate from Albums and the collection manager, retired on account/source replacement. Clearing filters never expands beyond the collection subset. Histograms and counts use that same subset; the library-wide year domain remains stable during filtering.

`createCollectionAlbums` shares ID-based, captured-owner/source admission between the pinned catalog and the small expansion in Collections. Malformed or missing references produce an explicit synchronization error, never a fallback to all albums. Pending pinned reads center their loader in the remaining content viewport below the shell header. Creating a derived collection from a pinned subset is unavailable, with an explanation: serializing only the extra browse filters would omit the saved base rule. Edit the existing rule through Collections; arbitrary rule composition remains Aède's responsibility.

## Dragging and verification

Only the dot grips start pointer or native HTML dragging in the shared object list. Row bodies keep the ordinary selection cursor and remain available for single/range selection and activation; keyboard ordering remains available through Alt+arrows.

The shared object list serves collections and excluded folders. Menu/object-list grips use the playback queue's five-pixel threshold, 35% source opacity, 65% floating preview and shadow. Pointer capture follows the row across lists. One two-pixel inset accent line marks each actual insertion gap: the upper half of a row and the lower half of its predecessor resolve to the same canonical line above that row. Empty tail space marks insertion after the final row. The same resolver controls pointer/native previews and release, without changing row geometry. Moving to the current position or leaving the destination shows no line. Exclusions and available collections reorder inside their own lists. Dragging a collection into the menus copies a shortcut and shows the line only in that destination; moving between lists clears the previous cue. The picker's presentation order exists only for the current Navigation visit/owner, follows immutable IDs through renames, and appends newly discovered IDs. It neither changes server rules nor writes menu preferences. Add/Enter publishes selected shortcuts in their displayed order with one saved operation. Escape, blur, pointer cancellation, disposal and replaced scopes discard the gesture and remove both preview and insertion feedback. Native HTML drag remains available, admitting local moves and external copies; arrow buttons and object-list Alt+arrows retain keyboard ordering. Cross-list collection drops recheck exact source/session and stable ID so a removed/recreated name cannot be admitted. Exclusion ordering remains a device-local presentation choice.

Tests cover persistence/migration, two-way canonical rename projection, multiple pins, delete/recreate, corrupt-data preservation, owner isolation, late reads, pagination, capability refusal and captured-session PATCH, plus deterministic drag lifecycle and opaque route/detail history. Fictional Storybook fixtures retain picker interactions. Software checks and a host App build do not establish Windows/Linux native interaction, remote live-server acceptance or physical audio behavior.

The legacy menu migration and settings row renderer remain cohesive modules above the usual size target: their version/order rules and row controls are kept together; ID policies, paging, pointer lifecycle, picker and workspace stay separate.
