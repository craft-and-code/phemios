# Queue composition

## Dedicated playlist workspace

The existing `playlists` route and navigation preference identity are retained, with the default label **Listes de lecture / Playlists**. This section opens the temporary session queue, not the M3U inventory. `PlaylistsPage` mounts the same `PlaybackQueue` adapter and occurrence editor as the Playback drawer; neither view copies, persists or initializes the queue. A new application/controller lifetime starts empty. Navigation, including the labelled header button to browse M3U files and its return action, never clears or starts it. Footer Play consumes the prepared order through the existing controller. In this view, a nonempty prepared list takes footer/Space-key priority over retained radio or podcast controls. Navigation and preparation do not stop those streams; starting the list uses the existing mutually exclusive transport admission. Empty lists and other views retain their normal external-stream controls. Account/session invalidation still retires its private playback selection.

The full-width workspace holds the count, file-browser entry and queue tools above its own row scroller. Only this standalone workspace supplies a decorative 40 px cached-cover slot between each removal cross and its track title. Missing artwork/album metadata keeps the same square with a disc glyph; the Playback drawer omits this column. Row clicks, removal, lyric controls and occurrence ids retain their contracts, and drag snapshots retain the thumbnail column. Thumbnail display reuses resident image URLs and never fetches while scrolling. Add/search, original/alphabetic/reverse order, drag, per-occurrence removal, lyrics, collection creation and clear use the same admission and callbacks as the drawer. Collections can therefore be created before playback starts. Queue-derived M3U publication/download controls are absent: server paths are not assumed to be portable to the client. The narrower Playback drawer releases one action slot; the dedicated workspace keeps its full width. `PlaybackQueueView` shares the chrome and empty state while keeping the drawer's Close action optional; standalone queues have no Close button. `PlaylistsView` owns only the temporary file-browser toggle. The M3U browser retains existing folder inventory, owner-private exports and downloads, loaded on explicit entry. Customized menu names, hidden entries and saved order retain their existing semantics.

The Playback queue has an explicit plus toggle before its existing toolbar actions. It opens an inline, focused search panel for tracks, albums, principal artists, existing M3U files/private exports and current-owner collections. Results and the existing queue scroll independently. A wider responsive drawer keeps its toolbar usable; narrow windows overlay the scene instead of compressing it. Search waits 250 ms after typing and reads bounded pages. Cached album/artist browsing performs no new network request and remains visible when its source is disconnected. Visibility never grants append permission: the shared account/source/output policy disables Add with a reason, and the player repeats admission before publishing any occurrence. Other-source cache entries remain searchable while only a local account is active; mixed origins are labelled. Tracks and owner-private collections/M3U still require the captured session for reads. Read failures remain explicit, including partial source failures.

The dedicated workspace search panel spans the available content width. The explicit **Tous / All** category combines bounded pages from each category and source, labels result types and prioritizes exact title matches. It preserves partial failures and retires the whole combined result on owner/generation replacement. The default remains Tracks so opening the picker does not start the extra category reads. Cached artist/album search excludes UUID fragments from free metadata matching, preventing short numeric queries from matching random MusicBrainz identifier segments; complete identifiers and actual numeric titles, aliases and annotation text remain searchable. This presentation rule does not change Aède's live track-query semantics. Empty search results centre their message within the scrollable result region without moving the search header or footer. A refused addition shows its reason in the row as well as in the disabled button tooltip; disconnected catalogue visibility never grants playback or private-data access.

Adding appends exact occurrences without replacing the current track, output, consumed clock, pause state or existing edited order. Repeated entries are intentional. An idle/stopped queue is prepared without starting audio. Footer Play starts the first retained occurrence in its edited queue order, before considering the visible page. The same queue remains available after Stop. An empty queue falls back to the current page; active playback retains Pause/Resume. Source admission follows the queued source, so an unavailable queue never silently becomes the visible album. Explicit contextual Play buttons still replace the queue. Source expansion leaves transport controls available; replacement/logout retires the captured selection, and an overlapping transport admission is refused. Native publication validates both queue identity and its expected size, with a maximum of 4096 occurrences. Pause and reorder remain on the existing queue; no seek or new history visit is issued by append itself. DSP preloading resolves the newly available successor from the shared bounded reference store, outside the audio callback.

Albums and principal artist discographies use Aède's existing playback ordering. Collections are evaluated against the latest owner-private rule at insertion time. M3U additions require the additive `m3u_playback_selection` capability and server-side resolution. Original file paths and URLs in previews remain inert in Phémios. Unresolved, ambiguous or non-file M3U entries refuse the whole insertion; no entry is silently discarded. A temporary check confirms a successful insertion.

Owner/session replacement hides search results immediately and prevents stale private selection publication. Closing the picker does not cancel an admitted addition, but the player still enforces its captured owner/selection lifetime. HQPlayer and mixed Local/Server queues remain explicitly unavailable; neither silently replaces the output or queue. Radio/podcast streams are outside this native catalogue queue contract.

The presentation boundary is available in Storybook under Media/QueueAdd. Unit tests cover paused/idle admission, original occurrence order, repetitions, owner replacement, source refusal, continued pause controls during expansion and bounded source searches. Native reference growth and current PCM signal/clock preservation have separate Rust regressions; physical acoustic continuity remains distinct from these checks.

## Contextual additions

When no native track is selected, the idle footer previews the album cover, track title and artist of the first prepared occurrence, including an exact track addition. The preview follows edited queue order and disappears on clear or account invalidation. It reuses cached artwork and the existing album/track/artist links without starting audio or assigning a current track, listening history, favourite control or playback clock. The idle instruction is hidden while these prepared details are visible. A later addition never replaces an actual current track's metadata; a first occurrence without album metadata keeps the ordinary cover placeholder while retaining its track title and artist label.

Rounded-square Play controls in list presentations opt into a contextual plus immediately before Play, at matching dimensions. Circular Album/Track detail actions and primary circular artist-card controls use a persistent small corner badge instead. Its separate hit target appends the exact album, track or principal artist reference without shifting or obscuring the centre of Play. The footer has no append badge. Its Stop action shares the append badge's geometry, surface, border, hover and focus rules, mirrored to the lower-right corner of Play. Radio and podcast Stop use the same CSS contract. Disabled corner badges retain an opaque surface and shadow over Play, dimming only the glyph rather than letting the accent circle show through. Its existing Play/Pause/Stop behavior is retained. Default cover overlays and Cover Flow retain their single Play control. Track-result rows, collection rows and mood track lists also expose square additions; the same source/session guards apply. Album/artist expansion reuses Aède's canonical presentation selection and the existing native append contract. Track additions narrow the canonical response to exactly one matching full reference, even when the server returns album context. They retain the track's original per-album number and total, and refuse missing or ambiguous matches without touching the queue. The inline track picker uses the same admission rule; explicitly expanded collections and M3U lists retain their ordered occurrences. A plus click stops propagation and never navigates, plays or replaces the current selection. The player exposes preparation/native failures through its existing visible error feedback; a confirmed insertion briefly changes the local plus to a check. Scope replacement retires that acknowledgement. Missing/read-only sessions, incompatible source queues and HQPlayer remain visibly disabled with a reason. A busy append prevents overlapping additions while unrelated transport controls remain usable during source expansion.

`PlaybackActionsView` owns the common square-action cluster, `CircularPlaybackActionsView` the overlaid circular badge, `QueueAppendView` their bounded pending/check lifecycle and `QueueAppend` their shared account/native admission. `CoverPlay` requires an explicit opt-in; default overlays and Cover Flow retain their original single Play control. Compact lists reserve the complete cluster width; editorial artist rows reserve their trailing column. Storybook exercises independent append/Play/navigation counters, equal square button dimensions, persistent badge geometry and disabled admission. The artist-card regression confirms the badge stays inside the card and leaves its main Play clickable. The badge stays visible without hover, is disabled during admission and briefly shows a check after acknowledgement; it adds no spinner or layout shift. No Play loader is introduced.

Playback admission is per reference and origin: a local account never authorizes disconnected server tracks, and a failed server connection probe disables remote Play/Add without disabling the local engine. The player repeats this check before and after audio configuration, before source-bound selection expansion and before publishing append results. Retained public catalog rows remain visible. The footer, detail controls and queue rows use the same policy; radio/podcast playback remains independent of Aède. Collections append their current owner's exact evaluated tracks through the existing bounded selection reader.

## Clearing the queue

A trailing trash action stops any owned native/HQPlayer playback and empties the transient queue without touching saved collections, M3U files or account preferences. Empty/busy queues disable it. The drawer stays open. Native clearing joins the worker before discarding occurrences, positions and retained track references, preserving output/policy/volume/repeat/crossfade configuration. HQPlayer keeps its verified connection; its owned playback stops and retained selection metadata is released.

The frontend discards rows only after receiving a validated empty idle acknowledgement. Failure retains the queue with visible error feedback and permits retry. In-flight selection expansion is retired so late success or failure cannot repopulate or overwrite the cleared queue. New source additions remain possible; library-owned lyric downloads retain their existing independent lifetime. This control clears transient playback state only and needs no destructive-data confirmation.

## Removing one occurrence

Each row places a small red unboxed close action immediately before its title, in a dedicated column optically aligned with the track number. The number/lyric leading region never delegates a click to row playback; only its dedicated lyric control acts there. Occurrences have stable slot ids, so removing a repeated reference deletes exactly one copy. A future/past occurrence is removed from the native active order without sending a transport command or changing the audible position. Removing the current stream waits for its actor to close it, then advances to the next occurrence in edited order, retaining Pause; at the tail it stops while leaving earlier rows available. The final occurrence clears the selection. Native reorder can only permute the retained active ids and cannot restore removed slots. Appending extends the same bounded slot store; stopped playback compacts the remaining selection on its next admission. Failures retain rows with visible feedback. HQPlayer currently refuses live single-occurrence removal explicitly.

The native slot count bounds retained occurrence ids; the visible count is the active order length. Public snapshots, next-track controls, original/numeric order and drag/sort helpers accept bounded sparse ids. Inactive/staged queue reorders stay local and do not restart audio. Full clear retains its separate stop-and-forget behavior.

During a DSP overlap, a non-current voice that already contributes buffered PCM is temporarily protected against removal; its close action is disabled with a tooltip until the overlap finishes. Reservation and occurrence edits share the same state mutex, so a removed preload cannot start mixing afterward. A captured successor's membership and retained reference are checked together before opening its source; concurrent removal cannot turn a cleared slot into an empty stream request. Native Stop releases the reservations. The currently displayed occurrence remains removable through the actor's confirmed stream-stop path.

## Reordering feedback and search admission

`QueueTrackRow` shares the production row presentation with the component explorer. A single pointer-transparent, inert copy follows pointer movement with a shadow while the original stays in place, faded. Pointer motion only updates its transform through one pending animation frame. Native HTML drag uses the same row snapshot. The drop marker is below a later target when moving down and above an earlier target when moving up, derived from edited positions rather than numeric ids; hovering the source itself has no marker. Drop edits exact occurrence ids; Escape, pointer cancellation/loss, window blur, scope replacement, a single-row queue and component disposal release the preview; disposal also removes the keyboard/blur listeners. The grip and native drag are unavailable with fewer than two occurrences. Keyboard Up/Down remains supported without triggering Play.

`createQueueSearch` separates the typed text from the admitted query. Changed input immediately retires the previous results during the 250 ms debounce, so old rows cannot be added accidentally. Enter and category changes submit the current text and cancel any timer that could reset later pagination. Owner/scope replacement and closing the panel reject late reads. Account-bound collection results cannot cross owners. Cached album/principal-artist search stays local; track/M3U reads preserve exact source, owner and query windows. M3U inventory and private-export reads fail independently, retaining accessible matches with explicit partial-error feedback. A clicked result must still belong to the currently confirmed result list before source expansion starts.
