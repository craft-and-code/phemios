# Native release preparation

The GitHub Release workflow follows Aède's separate App naming convention. Phémios has no CLI download: its private bundled Aède executable belongs to the App, while standalone Aède CLI releases remain in Aède's repository.

A push of a `vVERSION` tag builds installers on native macOS Apple Silicon, Windows x64 and Linux x86_64 runners. Ordinary branch pushes do not publish a release. Manual workflow dispatch builds downloadable Actions artifacts without publishing. Every expected installer must exist exactly once before packaging; ambiguous, missing or stale packages fail. SHA-256 sidecars accompany all downloads. The draft release is created only after every platform succeeds; a maintainer reviews it before publication.

Before tagging, align `Cargo.toml` workspace version, `package.json`, `package-lock.json` (root and root package), `src-tauri/tauri.conf.json` and Cargo lock workspace package versions. The release script checks npm/Cargo/Tauri agreement and tag equality. Cargo's locked build also checks its lockfile. Before compiling, the workflow resolves the latest published stable Aède release once and passes its tag/version/SHA to every platform. `scripts/audio-source.mjs` checks out that exact source, updates the shared dependency and lockfile, and fetches dependencies. Native preparation builds the bundled engine from the same selected source with `--locked --offline`, explicitly selecting the Rust host target and its source-local target directory so inherited Cargo output settings cannot substitute an old artifact; an old cached binary or a sibling checkout cannot substitute a different DSP. Development uses the same automatic policy. No manual pin edit is required after a stable Aède release.

A new workflow run, even for an old App tag, deliberately uses the latest stable Aède available when that run starts. Build logs, the workspace/lockfile, `.audio-source/selection.json` and bundled version metadata retain the selected SHA. API/network failure, moved release tags, modified cached sources and releases without shared audio fail before native compilation; no silent fallback is used. Native preparation requires network access even if dependencies are cached. Published Aède v0.6.1 predates the shared crates, so publish the next stable Aède version before attempting this automated build. The technical bootstrap tag is not a stable release and is not selected automatically.

The workflow overrides bundle targets explicitly: DMG on macOS, MSI/NSIS on Windows, and AppImage/DEB/RPM on Linux. The local `app` target remains unchanged. Installers are unsigned until signing credentials and platform signing/notarization are configured. No updater keys, credentials, signing certificates or developer accounts are committed. Intel Mac and ARM Linux targets can be added after native CI and device acceptance are available.

Packaging policy is tested with temporary installer fixtures via `node --test tests/release.test.mjs`; it does not build or run an App. Actual platform compilation, installer validation and native audio/device acceptance require a future GitHub run. The workflow is prepared here, not dispatched or claimed successful locally.
