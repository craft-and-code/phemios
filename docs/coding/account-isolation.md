# Account and source isolation review

The catalog remains shared. Artists, albums, tracks, graph facts, technical analyses and public presentation cache are catalog data, not an invented private library. Annotations, stars/ratings, tags/notes, collections, listening history, preferences, trophies, subscriptions and retained articles belong to an authenticated owner. Aède determines server ownership; Phémios binds presentation and native work to the chosen source and exact session.

## Corrected boundaries

The trophy loader previously continued from a delayed status response into an unlock POST after logout, same-account relogin, source replacement or disposal. Its captured reactive scope now admits the POST before dispatch and the result before publication; auditors perform a read. Failures remain local and retryable.

Native login/local-start publication now checks the generation that started it. Logout invalidates that generation even when no Client is published. Captured Client work is admitted before dispatch and after completion. The non-secret `nativeSession` process ticket additionally covers queued IPC handled after a replacement Client was installed; it is not an authentication credential or an owner selector. The desktop captures it before invocation. The flat playback IPC retains its established control fields and native States with one additional ticket; its local argument-count exception documents that compatibility constraint. Explicitly captured frontend sessions take precedence over a later wrapper ticket for private preferences reads/writes.

`aede_request` requires a ticket for mutations and private auth/me/admin reads, rechecks after service-key preflight and admits its final request separately. Public catalog reads and public radio/RSS/Wikipedia transport remain independent. Private M3U downloads admit the original ticket before fetching and again while publishing the bounded file. Playback starts admit the original ticket before preparing an authenticated stream, retaining the existing final Client/transport checks. A delayed Alice action cannot capture Bob and silently write Bob’s personal data/history.

Podcast subscriptions and listened evidence now use native documents private to source/authority/account. A feed fetch, unsubscribe confirmation or played-range callback captures its account scope; late results cannot populate or mutate the replacement scope. Logout/source replacement stops podcast playback. The page uses only the new native state. Legacy device-wide podcast and article localStorage is preserved byte-for-byte and is not imported or exposed to a new account automatically. The shared personal-source picker includes Podcasts and Encyclopaedia when both native sources are authenticated.

Saved Wikipedia articles use the same bounded private-document IO under a separate namespace. Both subsystems derive identity only from the actual native Client selected by source; IPC carries a generation ticket and narrow action payload, never an arbitrary owner, authority or path as a storage selector. Explicit backup restore also carries bounded origin attribution, which cannot select its destination. Managed Local uses a fixed engine authority and verified account ID, preserving identity across loopback-port changes. Remote identity uses the authenticated Client’s canonical server authority and stable account ID.

Private interface preferences use a separate anonymous base and an owner-scoped projection keyed by source/authority/account. The frontend admits reads, writes and delayed native acknowledgements against its captured session and preference generation. Legacy device-wide values are not silently assigned to a new account. Server-backed station favourites retain their own owner-scoped preference contract.

Portable preference backups now explicitly include the selected authenticated account’s podcasts/listened evidence and saved articles. Export captures the requesting profile and native session; import previews attribution and the current destination, then adds absent records without replacing existing identities. Both store budgets are validated before publication; a filesystem failure between the two atomic writes can leave safe additions and supports idempotent retry. Legacy unassigned records and all credentials remain excluded. See [backup contracts](../design/local-engine.md#portable-preferences-and-private-document-backup).

## Persistence and role policies

| State             | Native bound                                                      | Mutations                                                         |
| ----------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------- |
| Podcast metadata  | 100 feeds, 200 episodes/feed, 4 MiB serialized feed array         | Save/remove a subscription; review additive backup restore        |
| Listened evidence | 4096 markers, 4 MiB serialized marker array                       | Add listened evidence or reviewed backup; preserve on unsubscribe |
| Saved articles    | 40 articles, 3 MiB serialized article array; text 512 KiB/article | Save/remove an edition; review additive backup restore            |

Users/admins may mutate; auditors are refused in native policy, independently of disabled UI controls. Before a private-file mutation, a live authenticated session read verifies ID, enabled state and role outside locks. Native identity/generation is then checked again while bounded file IO commits under the source-session mutex. No network request runs while that mutex is held. Text bounds count UTF-16 units where the frontend does. Articles restrict retrieved timestamps to JavaScript Date bounds; podcast dates normalize to canonical ISO and validate real calendar/time ranges. Oversize or invalid writes retain existing file bytes and never evict personal records.

Stable filename digests are selectors, not authorization. Both reads and replacement writes validate exact retained owner, version and namespace, so foreign/colliding wrappers are refused. Unknown document-level fields survive supported narrow mutations; saving a feed or article replaces that row with the newly validated payload, rather than merging unknown row metadata. New Unix roots/files are 0700/0600; symlink/nonregular targets, broad file permissions and unsafe existing roots are refused without chmod or repair. Private configuration retains its existing preservation rules. Exclusive pending files, bounded reads and synchronized replacement prevent partial ordinary writes from publishing.

## Evidence and limits

Regression fixtures use fictional Clients and temporary roots only. Red tests reproduced late trophy POSTs, late native login/captured work, shared legacy podcast state, old-owner played evidence, missing command tickets, invalid UTF-16/date bounds and retained foreign/corrupt state. Tests cover account/authority/source isolation, same-owner new sessions, namespace mismatch, missing tickets, auditor refusals, unsafe roots/files, exact capacity and byte preservation. No source audio or tags are changed.

A server mutation already accepted before logout/revocation cannot be undone by the client. The live role probe and later local filesystem commit are not one atomic server transaction; native generation admission is atomic locally, not a server revocation lease. Retained reads require their current native principal, without claiming continuous online revocation validation. Explicit completed downloads remain user-owned artifacts outside the private browser state.

The source-session mutex serializes one application process. Two independent application instances can still race a same-owner read/modify/write before acquiring the exclusive pending file and lose one update; this is not cross-owner reassignment. Same-OS hostile path/ancestor replacement between metadata checks and open/rename remains a filesystem TOCTOU limitation; Windows inherited ACLs are not Unix-mode enforcement. OS IO on an unusual mounted application-data folder may block while the bounded native commit holds its mutex. An out-of-order login IPC response could retain an older desktop wrapper ticket and cause a refused operation; it cannot admit that ticket under a newer native generation.

The public cache is populated from explicit public presentation routes, not from private response caches. Its validator accepts additional public server fields; no reproducible private-data path through that cache was established.

The preceding account-isolation checkpoint gate passes on the host with 515 TypeScript, 14 Node, 148 core Rust and 15 bridge tests (692 total, none ignored), formatting, strict lint/TypeScript, frontend build/declarations, bridge compatibility, Rustdoc and native executable compilation. Targeted red-to-green fixtures and independent reviews support the boundaries described above. Separate debug QA and production macOS bundles build. The isolated [native acceptance record](ui-acceptance.md#account-isolation-radio-feedback-and-m3u-panes-2026-10-12) verifies article save/hide/restore across Local reconnection, logged-out podcast controls, ticketed synthetic playback, radio gestures and independent M3U panes. Neither the gate nor those scoped checks establish physical audio, other platforms or multi-device synchronization.

## Parental policy authority

Parental policies and usage belong to Aède and the immutable target account, independently for Local and Server. They are excluded from child-editable Phémios preferences and portable preference backup. Exact-owner optimistic administration, policy-stamped process-only catalogue projections and bounded media leases add restriction admission without making the shared catalogue private. Guest playback remains unrestricted by explicit choice. See the [parental-control design](../design/parental-controls.md) for contracts and enforcement limits.
