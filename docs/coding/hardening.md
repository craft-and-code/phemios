# Client hardening contracts

This document consolidates account, Library, Your music, Sources, Tools, search and settings reviews. It describes retained safeguards and their limits, not an exhaustive security certification. Regression details remain in the sibling/unit suites and Git history; current verification scope is in [current state](current-state.md).

## Accounts and private data

Native credentials never enter JavaScript preferences. IPC uses typed operations and bridge-version checks rather than broad shell/filesystem/HTTP permissions. Aède authorizes roles and private owners; frontend visibility is not authorization. Captured source/session identities and generations are checked before dispatch, between asynchronous stages and before publication. Returning to an equivalent account/reference must not revive an old result.

Idempotent HTTP reads retry busy responses (409/429/503) only while their captured native admission remains current, including the last retry. JSON, artwork, policy checks, private exports and transfer preparation retain that admission between attempts; mutations are not replayed. Retry waiting does not hold session locks. Retirement does not abort a socket already in flight, which retains its existing deadline.

Logout invalidates native ownership before cleanup. Native PCM, HQPlayer, remote token release and owned-engine shutdown are attempted independently, with combined errors retained. A successfully authenticated but unpublished remote client releases exactly its own token; accepted or successor sessions are untouched. Local engine Stop releases its process lease even when persisting disabled startup fails; that failure remains visible because a future launch may still auto-start. Frontend connection/start/stop continuations recheck provider lifetime after each awaited stage. A destroyed provider cannot restore a session, restart connectivity polling, initiate replacement authentication or change shared request routing. Already accepted native process ownership can remain available to a replacement frontend; retiring the old context does not log out that successor. Local native Start/Stop also reserve one process lifecycle order together with session capture/invalidation. Deferred engine work rechecks that order after obtaining the engine lock; an old shutdown cannot close a reconnected engine, and a retired start cannot reopen it or publish its login. Lifecycle admission is not held during process/network IO; final session publication is short and atomic with the next reservation. Local start/stop acknowledgements and errors also retain their operation generation: an older shutdown cannot clear a later accepted login, reroute requests or replace newer feedback, even while the same provider remains alive.

The managed `phemios-local` principal is protected only on the local source, by complete ASCII-case-insensitive name comparison; similarly prefixed or remote names are ordinary accounts. Private file writes confirm the current enabled same-owner user/admin role. Account deletion is not an Aède feature: disabling preserves data and revokes access. See [account isolation](account-isolation.md) and [parental controls](../design/parental-controls.md).

## Preferences and settings

Preference hydration/import validates all supported fields before transactional publication, retains previous bytes for rollback and preserves edits made during a pending account read. Failed rollback is explicit; unreadable stores are not reset. Device-only settings remain separate from account projections. Preference patches serialize within their current profile generation; an unresolved retired write cannot delay the replacement profile.

Service keys are deliberately device-wide. A late save/status response may finish its native operation but cannot change another interface profile's Fanart toggle, clear a successor draft or publish obsolete feedback. This is distinct from credential disclosure. Export/restore provenance and private podcast/article budgets are described in [local engine](../design/local-engine.md).

## Library and search

Public catalogue pagination has a shared 100 MiB serialization budget, including the envelope, artists and albums; page ownership transfers instead of cloning all strings. This is an input budget, not a bound on parsed JSON RSS. Exact source/session and catalogue epochs prevent late cache/bootstrap reads from replacing newer projections. A retained remote projection is visible to a connected session only when its canonical server address matches; an unavailable replacement catalogue cannot attribute old albums or its scan epoch to the new authority. Public browsing after logout and catalogue sharing between unsupervised accounts on the same server remain available. The managed local source retains its stable catalogue across ephemeral loopback ports. The frontend rechecks its captured catalogue/session lifetime after the parental preflight and before dispatching native synchronization; logout, local-engine shutdown or provider disposal cannot launch this next stage. Native catalogue synchronization also admits every policy, page and label-detail request to its captured session before/after IO. Logout or replacement stops follow-up requests while retaining the previous disk and process caches; an in-flight HTTP request may finish within its existing deadline. Paginated server-folder reads also recheck their read admission before each page and discard partial rows after cancellation, account replacement or disposal; only an already dispatched request may finish.

Private annotation pages publish only after complete validation, replace only their source, and preserve intervening confirmed writes. Detail resources and drafts become inaccessible immediately on logout/reference replacement. Personal tags remain search evidence, not factual genres. Filter-dependent requests retire on criteria changes; paging stops before further windows when its captured owner is retired. Label identities and secondary source reads follow the same admission policy.

Advanced Search captures the owner before capability lookup, forwards it to every request and checks admission before further windows or achievement writes. Its submitted expression/result window survives route remount within the same application session, but account/catalogue changes clear private state. Queue categories, debounce and pagination retire old searches. Local cached search describes its narrower scope instead of inventing unavailable file-tag evidence.

## Personal selections and downloads

Favourites, ratings, tags, moods and collections combine the shared catalogue with current-owner statements. Collection create/rename/delete/playback uses exact captured membership and owner admission. Drafts and name-bearing confirmations clear on replacement; a late save cannot close a successor dialog. History polling retains its visible list and updates only confirmed records.

M3U discovery excludes every account's private export subtree; private exports are read through owner-scoped routes. Download success/error belongs to the exact selected object and scope, including same-file reselection and account round trips. Already admitted filesystem work may finish; retiring feedback is not a promise to cancel it remotely.

Shared downloads propose confirmed green success only after publication. M3U/JSON/spectra/podcasts/article/biography/note downloads go to system Downloads with collision-safe names; CSV/themes/preference backups retain save dialogs. Notes export saved Markdown, not the editor draft. See [client contracts](../design/client-followup.md).

## Queue and audio

Background extraction-priority leases use named local/server selectors rather than entity-reference resolution, so local-only playback remains protected. Local and Server have independent renewal workers with at most one request in flight per source/login generation; a slow response cannot prevent the other source from renewing or releasing its six-second lease. Each login has a distinct lease key, including when both sources address the same server/account. Replacing or retiring a session disposes its worker and renewal timer immediately, so fresh work under the next login does not wait for a retired request. Each dispatch captures its exact source session; a retired request can finish within the native request deadline but cannot update or reschedule its successor. Cleanup never sends through a replacement login, and accepted old leases expire server-side. Pause or extraction completion attempts release once; a failed release leaves no cleanup timer or repeated POSTs, relying on the server expiry. Active or resumed playback still retries renewable priority heartbeats. Closing the application retires future dispatches; already accepted leases retain their server-side expiry.

The transient queue uses exact occurrences, not deduplicated references; append/removal/reorder/clear retain queue identity and bounded membership. Artist playback uses principal chronological discography rather than guest contributions. M3U expansion refuses ambiguous paths. The queue is bounded to 4,096 occurrences and initially renders 100 rows; cached thumbnails do not request network data during scroll. See [queue composition](../design/queue-composition.md).

Seek requests and waveform gestures capture reference, occurrence, queue and transport lifetimes. Ending/stopping/replacing that scope retires pending/coalesced seeks and pointer release; no old ticket may block or seek a successor. New catalogue/CD runs retire seek work before startup IO and their first snapshot, including same-reference/index restarts and HQPlayer queues without a queue identifier. An old acknowledgement or rejection cannot dispatch its coalesced choice into the replacement or clear a newer seek. Within the same live occurrence, a refused earlier seek does not discard a newer explicit coalesced choice; only that final choice can publish a refusal. This does not retry the refused position or survive scope retirement. Malformed seek acknowledgements still fail closed. A waveform drag admits one primary pointer; another contact cannot replace, move or cancel that gesture. Volume and crossfade coalesce unsent numeric choices within one transport/profile lifetime. Rapid mute toggles follow the latest queued volume intent in that same scope; a failed or retired intent cannot invert a later toggle. Unmute restores the last confirmed positive volume, never a rejected volume request. Crossfade and repeat modes accepted by the player remain live if preference storage fails; the save error stays visible, the persisted document remains unchanged, and later startup or a refused change retains those live values until profile reset. Startup waits for pending crossfade settings before applying their confirmed value, then waits for the current gain-setting queue and reapplies the confirmed gain if a newer choice overtook its own delayed reply; playback cannot start with that obsolete startup gain. Waiting for current settings does not wait for a retired profile’s worker. A reset or profile replacement admits a separate worker immediately; a retired acknowledgement or failure cannot block new dispatches, drain a successor’s pending choice or clear its serialization guard. Already admitted native commands may finish; retiring a frontend worker does not undo them. Audio action outcomes retain their interface profile even when another source keeps the global transport alive. Late repeat success cannot rewrite a replacement profile; obsolete DSP failures are hidden while valid transport polling and busy cleanup continue. Output rollback uses that command's outcome, not an unrelated volume error. Failures of a setting superseded by a newer queued choice do not publish obsolete feedback; final-choice failures and independent command errors remain visible. Crossfade success cannot erase independent feedback. A state snapshot requested before a confirmed volume change cannot restore its old gain in the footer; later snapshots still update the native clock and volume normally. Native Stop and Clear compare their reserved transport epoch against the last successfully accepted output under the shared routing lock before halting either local PCM or HQPlayer. A later pending or refused preparation cannot cancel shutdown of the old audio or clearing of its queue. A blocking worker delayed past a newer catalogue/CD start cannot stop or erase that successor. Local and remote logout cleanup also check the last successfully accepted output under routing before halting audio. A replacement login’s accepted catalogue/HQPlayer/CD output survives an older logout, while a pending or refused preparation does not exempt the old audio from cleanup. Reconnecting the local engine alone does not protect the retiring account’s audio, and stopping that old audio does not close the reconnected engine. The retired remote client’s credential revocation remains independent and never targets the successor. Catalogue and CD replacement recheck their captured transport/session admission after retiring the old output, because HQPlayer Stop and PCM worker shutdown can wait for IO. A cancellation or account change during that wait cannot activate or publish the pending replacement. CD session guards cover short checks and final publication, never the old-output retirement. Native buffering and failed-preload cancellation are documented in [audio continuity](../design/audio-continuity.md).

HQPlayer connection/disconnection requests retain an endpoint-configuration generation independent of transport intent. A deferred operation rechecks it under routing before protocol IO and before acknowledging its result; an old connect cannot reopen a disconnected endpoint or an old disconnect close its replacement. HQPlayer preparation captures endpoint generation and folder mappings together under routing, refuses a pending configuration and rechecks the captured profile between source requests and before replacing audio. Returning to identical mappings cannot revive an old preparation. These profile checks apply only to HQPlayer preparation and publication. Playlist upload rechecks transport, source-session and endpoint ownership between each XML command, including before and after Play. A superseded upload sends cleanup Stop and cannot publish accepted output. An already dispatched command may finish within the existing protocol deadline; cancellation does not interrupt that socket read. A naturally completed HQPlayer queue still owns its route; choosing a local output explicitly retires it before local gain, repeat or crossfade configuration. HQPlayer control errors distinguish local refusal from protocol/IO failure. Unsupported commands, invalid values and disabled settings report refusal without stopping audio or dropping the verified connection, including a pending local repeat/crossfade command that reaches the new HQPlayer route. Actual protocol/IO failures retain transport cleanup.

Radio, podcast and network-renderer admission share the same local-transport handoff check. An idle-looking native start or audio configuration that is still busy refuses the competing source; it cannot bypass Stop and produce concurrent audio. Active transport must confirm Stop before external media starts. The media's own cancellation and account guards still run after that awaited handoff. Browser media wait for the current native gain queue before inheriting volume, then recheck their playback attempt and account. Replacing a station or episode while that inheritance is pending retains the wait; a newer explicit gain can supersede it without admitting the retired selection. A newer browser gain or mute takes precedence over inherited gain and retires unsent native choices; late native acknowledgements or failures cannot rewrite that gain or its preferences. Already admitted native controls may still finish. Profile changes and transport retirement also retire gain ownership. Browser unmute reads the shared current-profile positive gain rather than a value retained from an earlier source or account, including when that media inherited mute. Keyboard Mute and Stop follow the resident podcast/radio before the catalogue transport, including during browser preparation; unrelated native busy state cannot block their cancellation. Previous/Next do not dispatch into a retained native queue while a browser source owns audio. Space keeps a selected browser source authoritative even while connecting or after failure/end: connecting is inert, while paused/failed/completed media resume that source instead of falling through to a contextual album. A nonempty prepared list retains its explicit keyboard priority. Contextual Play and prepared-list selection retain their separate policy.

Queue lyric jobs belong to the account/application rather than the drawer. Check admission before/after each source-capability read; Stop prevents the next dispatch. Late cancellation errors cannot overwrite a newer batch, and completed private diagnostics do not reappear after logout/return. Available lyrics, individual acquisition and bulk acquisition retain separate controls without bubbling into playback.

## Sources and external services

Radio directory/search/resolution is independent of Aède login; only favourites are personal. Official authorities, validated-response failover, a shared 24-second directory operation budget and at most eight seconds per request bound native browsing. Startup/waiting has a single stall deadline; pause/disposal supersedes pending play attempts. Podcast Pause also retires preparation before media creation; explicit Resume admits only the new attempt. Account replacement stops private podcast playback.

Native RSS/download requests validate public DNS addresses on every redirect; provider diagnostics redact secrets. Browser media shares literal address admission and carries no Aède bearer. **HTMLAudioElement does not provide DNS-rebinding or redirect isolation**: a public name can later reach a private address. A future native media boundary must cover HLS children, ranges, codecs and cancellation; one DNS preflight is insufficient. See [source contracts](../design/native-integration.md).

JamBase uses fixed HTTPS requests, protected authorization, bounded pages and persisted locked fail-closed budgeting. Live service availability, provider quotas outside this installation and real hardware are not proven by mocks. CD/CUE remains local and cannot bypass supervised-account rules. Its periodic native permission check retains one captured pair of Local/Server identities. Every policy attempt, including busy retries, rechecks both generations outside network IO; logout, same-account replacement or a login on the other source retires that permission. Guests still require no server.

## Tools and saved prose

Analysis import/progressive results, diagnostics/statistics, transfers and encyclopedia readers capture owner/reference/lifetime. Old read/cancel/progress callbacks cannot overwrite a new view/account. Transfers keep selected-file previews, destination identity, conversion naming and publication checks separate; output paths are not arbitrary source-write grants. Transfer start/cancel acknowledgements and diagnostics use the same exact account-generation and disposal admission as progress reads; a late command reply cannot publish into the next account or refresh its view.

Biographies and encyclopedia text are rendered inertly, with attribution. Retained resource links use a shared browser-compatible URL policy in Rust and TypeScript; unsafe address forms cannot enter cache or private saved articles. Saved copies preserve validated resources, TOC and reader navigation. Private articles/podcasts retain their owner even when the public text/catalogue is common. Their mutation queues belong to the exact login/source: replacing that scope admits new writes independently, while old replies and queued mutations stay retired. Reloading podcast state within the same scope preserves write order. See [biographies](../design/client-followup.md) and the native article/cache contracts.

## Security and performance limits

The trusted OS operator can read private stores/backups and alter installation configuration; HTTP account separation does not sandbox that operator. Unsafe existing config objects are preserved, and bounded reads refuse corrupt data rather than replacing it. Filesystem admission retains documented TOCTOU/platform limits.

[Dependency findings](dependencies.md) and Aède's desktop dependency policy remain release follow-ups, particularly Linux GTK3 advisories and maintenance warnings. Past advisory checks are dated evidence, not current guarantees. Cache quotas/pruning, decoded artwork residency, physical audio/copy acceptance, minimum Rust and other-platform behavior remain separate work. See the [audio](audio-performance.md) and [visualizer](visualizer-performance.md) measurements; algorithmic reductions alone are not whole-app FPS/RSS claims.
