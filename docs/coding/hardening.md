# Hardening checkpoint

This review covers the checked-in Phémios client and its dependency lockfiles on 2026-10-11. It is a focused code and regression review, not a penetration-test certificate, exhaustive coverage claim or cross-platform acceptance. Aède's source and the user's music files are outside this change. Cover Flow's renderer, policies and animation are left intact.

## Boundaries examined

The review follows source/account replacement and late replies, native IPC admission, protected configuration and exports, catalog response size, provider authority/redirect/TLS policy, browser rendering of external text, media lifetimes and generated Rust/TypeScript documentation. The WebView has no generic shell, filesystem or HTTP plugin permission. Typed native operations validate bridge compatibility; domain roles remain enforced by Aède. Tokens remain native, not in JavaScript preferences. Notes retain Markdown as inert content; provider biographies/articles do not insert executable HTML.

## Provider availability

Unauthenticated host checks reproduced HTTP 503 from Radio Browser's aggregate authority and documented German mirror. The provider's DNS SRV record advertised only that mirror during the check. Subsequent standard and public-resolver ureq probes also observed connection resets; curl still observed HTTP 503. The added resolver is not the cause of that difference. Logging in to Aède cannot repair a provider outage. The client now distinguishes unavailable service, rate limiting, timeout, secure connection and invalid answers. It does not substitute invented stations, arbitrary mirror authorities or an Aède dependency. The live result is an observed provider failure, not successful live radio playback.

Authority and API contracts: [Radio Browser API documentation](https://docs.radio-browser.info/). Address scope uses the [IANA IPv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry).

## Dependency review and remaining risks

`npm audit --json` completed successfully with zero reported advisories for the complete npm lockfile, including development dependencies. No dependency is added or upgraded by this lot.

Cargo.lock was reviewed against the official [RustSec advisory database](https://github.com/RustSec/advisory-db), commit `7eebec69c352c7191b1f13eb95dd510eeca5d1de`. This was a lockfile/advisory comparison; `cargo-audit` is not installed and its output is not claimed. The resolved Tauri version includes its published [source-validation fix](https://github.com/tauri-apps/tauri/security/advisories/GHSA-w28w-mhc8-qvjv).

The Linux GTK dependency chain retains `glib 0.18.5`, affected by [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html). It is not compiled for this macOS target, and Phémios has no direct use of the affected `VariantStrIter`; this does not establish that every upstream use is unreachable on Linux. The compatible Tauri/GTK chain must be reassessed before a Linux distribution. Maintenance notices also concern `rustls-pemfile` through tungstenite and `proc-macro-error` through GTK. They remain upstream follow-up items, not demonstrated application exploits or reasons to silently replace the platform stack.

Native RSS reading and podcast downloading validate public DNS addresses through the connector, including each redirect. Radio directory access is likewise native and restricted. Radio and podcast **media playback** still uses `HTMLAudioElement`: literal URL validation cannot prevent a public name resolving privately, rebinding or redirecting to a private address. Media fetches carry no Aède bearer token, but the operating system's WebView still controls those network connections. A complete fix needs a separately designed native streaming boundary with HLS child requests, range seeking, cancellation and platform codec acceptance; a one-time DNS preflight would not close that boundary. Do not claim complete SSRF isolation for WebView media.

Cache quota/pruning, decoded artwork working sets, physical audio/copy acceptance, minimum Rust toolchain execution and Windows/Linux host acceptance remain separate work. Maximum catalog serialization size limits retained input; it is not an exact allocator/RSS bound for a parsed JSON tree.

## Follow-up lifetime review

A second focused pass reproduces and closes native catalog publication after logout/relogin, a stale initial-cache read superseding a newer synchronization, and late startup IPC restoring an old frontend projection. Native publication admits the exact client credentials; retained-cache reads use captured Arc identity. Network/cache reads and response cloning stay outside the retained-projection mutex. Frontend revisions and full session objects admit each source independently, including automatic local startup. No Cover Flow renderer or artwork policy change is involved.

Radio Browser's directory, statistics and stream resolution are directly invoked by Phémios without an Aède principal or bearer token. Its WebView media player is independent too; starting it only stops an already active catalogue/podcast transport. Account-private preferences hold radio favourites. During the follow-up, the provider recovered: the actual native directory returned HTTPS station pages for France and the United States. Isolated macOS WebView playback reached its playing/live state for RMC with the local engine stopped and no server account. United States directory results also loaded without an account; a SomaFM stream aborted during host playback, so success is not claimed for every provider entry. Application volume was zero; this proves host playback admission and does not claim physical acoustic acceptance. Earlier outage observations remain historical evidence, not a persistent provider status.

Further corrected contracts include submitted-criteria radio search coalescing without old-country results after failure, bounded stream startup even with repeated waiting events, preservation of chosen radio volume after failure, translated active-startup abort guidance, and refusal to resurrect disposed players. Podcast play-attempt admission preserves pause/resume against old play-promise rejections. Account audio restoration retains its event listener across ordinary transport resets; only final disposal removes it. Queue lyrics hide retained availability and title-bearing feedback immediately after owner replacement. Personal collection drafts and action acknowledgements belong to an exact view/session generation. All new collection creation routes request `create_only`, so a name collision cannot silently replace a saved rule. Themed selectors reveal their selected row and support bounded accent-insensitive keyboard prefixes and repeated-letter cycling. A native WebKit failure reproduced click-to-open without keyboard focus; explicit trigger focus admits the same keyboard path on macOS. Country-name formatters are retained lazily per FR/EN locale rather than reconstructed for each comparison. An isolated Node/ICU benchmark over the actual 177-country sort and labels retained identical output and reduced median work from 9.479 to 1.749 ms in French and 8.719 to 1.734 ms in English. This measures that computation, not whole-app/native rendering speed.

A compiled-JSX browser reproduction exposed hundreds of undisposed Solid computations during globe redraw: the frame callback repeatedly read a conditional JSX prop getter without its component owner. Owned reactive snapshots now retain the selected/available country sets, and frame/pointer handlers only read those snapshots. After reloading the patched app, selecting a country, rotating the globe and leaving/remounting Radio produced no new unowned-computation warnings. The temporary first-stack instrumentation was removed; diagnostics are not suppressed.

The same WebView media DNS/redirect limits, Linux GTK advisory, cache quotas and cross-platform/physical acceptance limits described above still apply. No new dependency or Aède source change is introduced. Tests and final host observations are recorded in current state.

## External-service credential follow-up

The 2026-10-12 follow-up traces app-owned Fanart.tv, AcoustID and Ticketmaster credentials through configuration, IPC status, preference export, explicit job preparation, child processes and provider diagnostics. It uses fictional keys and disposable stores; no real credential/profile is inspected or changed.

Private native configuration keeps mode 0600 on Unix. Newly created app-owned configuration directories use mode 0700. An existing directory that is a symlink or group/world-writable is refused before private reads and publication, without changing its permissions, target or retained contents. Existing safe directories retain their permissions. Corrupt stores remain refused and preserved. This checks the root metadata; it is not race-proof descriptor confinement of every ancestor and does not establish Windows ACL acceptance. These are private files under the OS account, not encrypted keychain storage.

Public configuration exposes presence only. Saved-preference/theme exports and account preferences exclude keys and bearer tokens. The WebView holds an entered password-field draft only until explicit native saving succeeds; it never receives configured key values. The owned engine excludes app keys from its retained startup environment. Explicit enrichment uses the existing bounded authenticated service-key contract; Ticketmaster uses its fixed HTTPS authority, refuses redirects and returns generic failures without its key-bearing request URL.

A reproduced diagnostic failure left a longer key's suffix visible after a shorter overlapping key had been replaced first. Aède now masks merged spans in the original diagnostic text, including raw/trimmed/encoded variants and overlapping occurrences, without processing generated markers again. Captured/truncated job output retains its 64 KiB contract. Direct and Unix-delegated AcoustID identify failures use the same masking for provider messages and transport diagnostics without changing retry/stop classes. Server keys and explicit per-job overrides keep their original scope.

An invalid retained Ticketmaster value can be removed explicitly without reading it as a valid key or discarding unrelated settings. Settings permits the native removal attempt after a presence-read error; malformed global configuration still refuses the operation. Tests cover unchanged targets/permissions, unknown retained fields and corrupt-store refusal.

Private annotation response validation also requires the outer target reference when an annotation is absent. Invalid GET/PUT replies cannot erase a different item's confirmed projection; writer publication remains inside its captured active owner. All canonical Aède annotation kinds and literal reference-key text remain supported.

Existing trusted Aède/FFmpeg/fpcalc helpers may inherit their process environment; this lot does not isolate all children or erase credentials already captured by running jobs. The earlier media-DNS, cache-quota, Linux dependency and physical/cross-platform limits remain separate. This is a focused code and regression review, not a guarantee against every flaw or a protection boundary against a privileged process controlling the same OS account.
