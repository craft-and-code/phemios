# Hardening checkpoint

This review covers the checked-in Phémios client and its dependency lockfiles on 2026-10-11. It is a focused code and regression review, not a penetration-test certificate, exhaustive coverage claim or cross-platform acceptance. Aède's source and the user's music files are outside this change. Cover Flow's renderer, policies and animation are left intact.

## Boundaries examined

The review follows source/account replacement and late replies, native IPC admission, protected configuration and exports, catalog response size, provider authority/redirect/TLS policy, browser rendering of external text, media lifetimes and generated Rust/TypeScript documentation. The WebView has no generic shell, filesystem or HTTP plugin permission. Typed native operations validate bridge compatibility; domain roles remain enforced by Aède. Tokens remain native, not in JavaScript preferences. Notes retain Markdown as inert content; provider biographies/articles do not insert executable HTML.

## Provider availability

Unauthenticated host checks reproduced HTTP 503 from Radio Browser's aggregate authority and documented German mirror. The provider's DNS SRV record advertised only that mirror during the check. Subsequent standard and public-resolver ureq probes also observed connection resets; curl still observed HTTP 503. The added resolver is not the cause of that difference. Logging in to Aède cannot repair a provider outage. The client now distinguishes unavailable service, rate limiting, timeout, secure connection and invalid answers. It does not substitute invented stations, arbitrary mirror authorities or an Aède dependency. The live result is an observed provider failure, not successful live radio playback.

Authority and API contracts: [Radio Browser API documentation](https://docs.radio-browser.info/). Address scope uses the [IANA IPv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry).

## Dependency review and remaining risks

`npm audit --json` completed successfully with zero reported advisories for the complete npm lockfile, including development dependencies. No dependency is added or upgraded by this lot.

Cargo.lock was reviewed against the official [RustSec advisory database](https://github.com/RustSec/advisory-db), commit `7eebec69c352c7191b1f13eb95dd510eeca5d1de`. This was a lockfile/advisory comparison; `cargo-audit` is not installed and its output is not claimed. The resolved Tauri version includes its published [source-validation fix](https://github.com/tauri-apps/tauri/security/advisories/GHSA-w28w-mhc8-qvjv).

The Linux GTK dependency chain retains `glib 0.18.5`, affected by [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html). It is not compiled for this macOS target, and Phémios has no direct use of the affected `VariantStrIter`; this does not establish that every upstream use is unreachable on Linux. The compatible Tauri/GTK chain must be reassessed before a Linux distribution. Maintenance notices also concern `rustls-pemfile` through tungstenite and `proc-macro-error` through GTK. They remain upstream follow-up items, not demonstrated application exploits or reasons to silently replace the platform stack.

Native RSS reading and podcast downloading validate public DNS addresses through the connector, including each redirect. Radio directory access is likewise native and restricted. Radio and podcast **media playback** still uses `HTMLAudioElement`: literal URL validation cannot prevent a public name resolving privately, rebinding or redirecting to a private address. Media fetches carry no Aède bearer token, but the operating system's WebView still controls those network connections. A complete fix needs a separately designed native streaming boundary with HLS child requests, range seeking, cancellation and platform codec acceptance; a one-time DNS preflight would not close that boundary. Do not claim complete SSRF isolation for WebView media.

Cache quota/pruning, decoded artwork working sets, physical audio/copy acceptance, minimum Rust toolchain execution and Windows/Linux host acceptance remain separate work. Maximum catalog serialization size limits retained input; it is not an exact allocator/RSS bound for a parsed JSON tree.

## Documentation and verification

README descriptions are corrected for current missing-discography placement, settings sections, concert-key placement and account-owned radio favourites. TypeScript declaration output preserves authored JSDoc; formal TSDoc comment-coverage validation is not installed. Rustdoc and Clippy treat warnings as errors. Contract comments describe the added size, ownership and failure behavior, with test fixtures kept outside production modules.
